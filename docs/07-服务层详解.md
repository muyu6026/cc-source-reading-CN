## 7.2 `mcp/` —— 连接外部工具（23 文件 · 12311 行）
**MCP = Model Context Protocol（模型上下文协议）**，是 Claude 调用"外部世界工具"的标准方式。本地命令行工具、数据库、浏览器、第三方 API，都可以通过 MCP 接入。

### `mcp/client.ts` —— 支持 4 种传输方式

> 📁 本节源码：[`src/services/mcp/client.ts:8-16`](../source/src/services/mcp/client.ts#L8-L16)

```ts
// src/services/mcp/client.ts:8-16
import { SSEClientTransport } from '@modelcontextprotocol/sdk/client/sse.js'
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js'
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js'
// 翻译：Stdio=标准输入输出(本地子进程) / SSE=服务器推送事件(远程) / StreamableHTTP=可流式 HTTP
```

| 传输方式 | 中文 | 适用场景 |
|----------|------|----------|
| **Stdio** | 标准输入输出 | 最常见。Claude Code 起一个本地子进程，通过 stdin/stdout 跟它聊 JSON-RPC |
| **SSE** | 服务器推送事件 | 远程服务器（老式） |
| **StreamableHTTP** | 可流式 HTTP | 远程服务器（新式，推荐） |
| **WebSocket** | 双向长连接 | 需要持续双向通信时（见 `McpWebSocketServerConfig`） |

### `mcp/config.ts` —— 从哪读"要连哪些服务器"
从**多层配置**汇总：

| 来源 | 位置 | 说明 |
|------|------|------|
| 全局 | `~/.claude.json` | 用户级 |
| 项目 | `.mcp.json` | 项目级 |
| 插件 | 插件自带 | 插件安装的 MCP 服务器 |
| 企业托管 | managed settings | 公司强制下发 |

它区分配置范围 `ConfigScope`，并定义多种服务器类型：

```ts
McpStdioServerConfig      // 本地命令启动
McpHTTPServerConfig       // HTTP
McpSSEServerConfig        // SSE
McpWebSocketServerConfig  // WebSocket
```

还包含 `expandEnvVarsInString` —— 把配置里的 `$VAR` 展开成环境变量（所以你可以在 `.mcp.json` 里写 `"${HOME}/tools"` 这种路径）。

### `mcp/` 其他关键文件
| 文件 | 作用 |
|------|------|
| `auth.ts` | MCP 服务器的 OAuth 授权（有些远程 MCP 需要登录） |
| `MCPConnectionManager.tsx` | 管理所有 MCP 连接的生命周期（启动 / 重连 / 断开） |
| `channelAllowlist.ts` / `channelPermissions.ts` | 频道白名单与权限 |
| `envExpansion.ts` | 环境变量展开 |
| `officialRegistry.ts` | 官方服务器注册表 |
| `utils.ts` | `isMcpTool()` 等工具函数（判断"这工具是不是 MCP 来的"） |
| `oauthPort.ts` | OAuth 回调端口 |
| `elicitationHandler.ts` | 处理 MCP 的"询问用户"请求 |

> **学习要点**：想懂"Claude 怎么用你的本地工具"，把 `mcp/client.ts`（连接）+ `mcp/config.ts`（配置）+ `mcp/auth.ts`（授权）三个读透就够了。

## 7.3 `analytics/` —— 埋点、遥测、功能开关（9 文件 · 4040 行）
### `analytics/index.ts` —— 零依赖设计

> 📁 本节源码：[`src/services/analytics/index.ts:11-19`](../source/src/services/analytics/index.ts#L11-L19)

```ts
// src/services/analytics/index.ts:11-19
// DESIGN: This module has NO dependencies to avoid import cycles.
// Events are queued until attachAnalyticsSink() is called during app init.
// The sink handles routing to Datadog and 1P event logging.
// 翻译：本模块零依赖，避免循环引用；事件先排队，等初始化时挂上"sink(收集器)"才上报。
```

**为什么"零依赖"？** 因为几乎每个模块都要打点（`logEvent`），如果 analytics 自己又依赖别的模块，就会形成循环引用。所以它刻意做成"**谁都不依赖，只被依赖**"，事件先入队，等启动完成再统一上报。

### 那个超长的类型名是一个"安全标记"
源码里到处出现：

```ts
AnalyticsMetadata_I_VERIFIED_THIS_IS_NOT_CODE_OR_FILEPATHS
```

它的值其实是 `never`。这是个**编译期安全门**：开发者必须显式写 `myString as AnalyticsMetadata_I_VERIFIED_THIS_IS_NOT_CODE_OR_FILEPATHS` 才能把字符串塞进埋点，等于在代码里"签名保证"——**我打点的这个字符串里不含代码 / 文件路径等敏感信息**。编译期就拦住隐私泄露。

> 这种"用一个不可能赋值的类型做标记"的技巧叫**品牌类型（branded type）**，非常值得学。

### `analytics/growthbook.ts` —— 运行时功能开关
接 **GrowthBook**（第三方 A/B 实验 / 功能开关平台）。这是 `feature('XXX')`（**构建期**开关）的"**运行时** cousin"：

| 开关类型 | 何时决定 | 例子 |
|----------|----------|------|
| `feature('XXX')`（Bun） | **构建期**，决定代码是否保留 | `feature('KAIROS')` |
| `getFeatureValue_CACHED_MAY_BE_STALE()`（GrowthBook） | **运行时**，按用户分组开关 | 灰度发布、A/B 实验 |

### `analytics/` 其他文件
| 文件 | 作用 |
|------|------|
| `datadog.ts` | 把事件发到 Datadog（监控平台） |
| `firstPartyEventLogger.ts` | 发送到 Anthropic 自家（first-party）事件日志 |
| `sink.ts` | 收集器路由（决定事件发去哪） |
| `sinkKillswitch.ts` | 一键关闭埋点的"紧急开关" |
| `metadata.ts` | 埋点元数据处理（`sanitizeToolNameForAnalytics` 等） |
| `config.ts` | 埋点配置 |

> `firstPartyEventLogger.ts` 里有条 PII 特殊通道：`_PROTO_*` 开头的字段会被单独提到 proto 的受控列，普通后端（Datadog）看不到——这是"敏感字段走特权通道"的设计。

## 7.4 `lsp/` —— 代码智能（7 文件 · 2460 行）
**LSP = Language Server Protocol（语言服务器协议）**，让编辑器获得"跳转到定义""报错诊断"等能力。

### `lsp/manager.ts` —— 全局单例 + 状态机

> 📁 本节源码：[`src/services/lsp/manager.ts:14-25`](../source/src/services/lsp/manager.ts#L14-L25)

```ts
// src/services/lsp/manager.ts:14-25
type InitializationState = 'not-started' | 'pending' | 'success' | 'failed'
let lspManagerInstance: LSPServerManager | undefined
let initializationState: InitializationState = 'not-started'
let initializationGeneration = 0   // 翻译：代次计数，防止过期初始化覆盖新状态
```

**`initializationGeneration` 解决什么问题？**
假设你连续触发了两次初始化：第 1 次很慢、第 2 次很快。如果第 2 次先成功、第 1 次后失败，那个"迟到的失败"会把状态改回 `failed`，覆盖掉正确的成功状态。加个"代次计数器"，**只有当前代次的初始化才能改状态**，迟到的旧结果直接丢弃。

### `lsp/` 文件分工
| 文件 | 作用 |
|------|------|
| `manager.ts` | 全局单例管理、初始化状态机 |
| `LSPClient.ts` | 单个语言服务器的客户端 |
| `LSPServerManager.ts` | 管多个服务器的启停 |
| `LSPServerInstance.ts` | 单个服务器实例 |
| `LSPDiagnosticRegistry.ts` | 收集诊断（红波浪线那种报错） |
| `passiveFeedback.ts` | 把诊断结果"被动"喂回给 AI 当上下文 |
| `config.ts` | LSP 配置 |

> **passiveFeedback** 是个聪明设计：AI 改完代码，语言服务器的报错会**自动**作为上下文喂回去，不需要 AI 主动去查。相当于"AI 自带编译器反馈"。

## 7.6 记忆系统：`SessionMemory/` + `extractMemories/` + `autoDream/` + `teamMemorySync/`
这是"让 Claude 记住你"的能力，含**英文 prompt**（你点名要翻译的）。

### `extractMemories/prompts.ts` —— 给 AI 的"怎么存记忆"指令

> 📁 本节源码：[`src/services/extractMemories/prompts.ts:57-66`](../source/src/services/extractMemories/prompts.ts#L57-L66)

```ts
// src/services/extractMemories/prompts.ts:57-66 （节选，原文是英文提示词）
'## How to save memories'                              // "## 怎么存记忆"
'Write each memory to its own file (e.g., `user_role.md`) using this frontmatter format:'
// 翻译：把每条记忆写成独立文件，用下面的 frontmatter 格式
'- Organize memory semantically by topic, not chronologically'  // 按主题而非时间组织
'- Update or remove memories that turn out to be wrong or outdated' // 错的/过时的就更新或删
'- Do not write duplicate memories. First check if there is an existing memory you can update'
// 翻译：别写重复记忆，先看看有没有现成的能更新
```

**`MEMORY.md` 的关键规则**（提示词里写得很明确）：

- `MEMORY.md` 是**索引文件，不是记忆本身**；
- 它**永远被塞进 system prompt**，超过 200 行会被截断，所以要保持简洁；
- 每条索引一行、约 150 字符以内，格式是「标题链接 + 记忆文件名 + 一句话钩子」；
- **绝不能**把记忆内容直接写进 `MEMORY.md`。

> 这是个很值得抄的"记忆架构"：**索引 + 分文件**。索引小、常驻上下文；详情大、按需读取。

| `SessionMemory/sessionMemoryUtils.ts` | 记忆工具函数 |
| `SessionMemory/prompts.ts` | 会话记忆的提示词 |
| `extractMemories/extractMemories.ts` | 从对话中抽取记忆 |
| `extractMemories/prompts.ts` | 抽取提示词（上文） |
| `autoDream/autoDream.ts` | "自动做梦"：后台空闲时自动整理 / 合并记忆 |
