## 7.2 谁在调 services

服务层不主动跑，它被上层 `import`。下面这张图是按真实 import 关系画的，括号里是「上层有多少个文件出现该子路径」（统计口径见本节验证命令）。

```
入口   entrypoints/cli.tsx → main.tsx / cli/print.ts
         │
应用   query.ts      tools/        commands/     hooks/       components/
       主循环        工具执行       斜杠命令      生命周期      React/Ink
         └──────────────┴──────────────┴─────────────┴─────────────┘
                                    │ import
服务                       src/services/  130 文件 53,683 行
分支   api/(57)    mcp/(82)    lsp/(12)    oauth/(17)    analytics/(290)   compact/(20)
       调模型       连外部工具   诊断附件     登录/续期      埋点+开关          压上下文
```

两个方向要分清：

- **向上**：`query.ts` 只认识 `callModel/microcompact/autocompact` 三个服务函数（外加一个 `uuid` 生成器）（[`query/deps.ts:21`](../source/src/query/deps.ts#L21) 的 `QueryDeps`），具体实现由 [`productionDeps()`](../source/src/query/deps.ts#L21) 注入。服务层对主循环是「可替换的零件」，这是 7.10 要讲的约定一。
- **向内**：40 个 `services/` 内部文件反过来 import `analytics/index.ts`，而 `analytics/index.ts` **一个 import 都没有**（实测 `grep -c '^import'` 得 0）。这条单向边让「谁都能打点」不会变成循环引用。

```bash
python - <<'PY'
import os,re,collections
c=collections.Counter()
for dp,_,fs in os.walk('source/src'):
    for f in fs:
        if not f.endswith(('.ts','.tsx')): continue
        p=os.path.join(dp,f); r=os.path.relpath(p,'source/src').replace('\\','/')
        if r.startswith('services/'): continue
        for m in set(re.findall(r"services/(\w+)", open(p,encoding='utf-8',errors='ignore').read())): c[m]+=1
for k in ['analytics','mcp','api','compact','oauth','lsp']: print(f'{k:10}{c[k]}')
PY
```

实际输出：`analytics 290`、`mcp 82`、`api 57`、`compact 20`、`oauth 17`、`lsp 12`。口径是「上层文件中出现 `services/<名>` 路径的次数」，含注释里的提及，所以比纯 import 略高。

## 7.3 ① API 层：一次请求怎么组装，错了怎么办

`api/` 20 文件 10,477 行，是全服务层第二重的目录。三个代表文件：

| 文件 | 行数 | 在整条链路的哪一格 |
| --- | ---: | --- |
| [`claude.ts`](../annotated/src/services/api/claude.ts#L2493) | 3,419 | **组装 + 发车**：把 `Message[]`、系统提示、工具表拼成一次 `beta.messages.create` |
| [`withRetry.ts`](../annotated/src/services/api/withRetry.ts#L105) | 822 | **发车后的容错**：包住 SDK，决定「重试 / 换模型 / 放弃」 |
| [`errors.ts`](../annotated/src/services/api/errors.ts#L557) | 1,207 | **失败转消息**：把异常翻译成一条可见的 `AssistantMessage` |

### 一次请求的六个组装动作

顺序写在 `queryModel` 里，从上到下就是执行顺序：

1. **工具表**：`filteredTools.map(toolToAPISchema)`，MCP 工具在这一步才变成 API 认识的 JSON Schema（[`claude.ts:1237`](../annotated/src/services/api/claude.ts#L1623)）。
2. **消息归一化**：`normalizeMessagesForAPI(messages, filteredTools)`（`claude.ts:1266`）。
3. **配对修复**：`ensureToolResultPairing(messagesForAPI)`，给孤儿 `tool_use` 补合成 `tool_result`（[`claude.ts:1301`](../annotated/src/services/api/claude.ts#L1710)）。
4. **系统提示分块**：`buildSystemPromptBlocks(systemPrompt, enablePromptCaching, …)`，缓存标记打在这一层（`claude.ts:1376`）。
5. **消息级缓存断点**：`addCacheBreakpoints(...)`，注释明确「每次请求**恰好一个** message 级 `cache_control` 标记」（[`claude.ts:1701`](../annotated/src/services/api/claude.ts#L2307)）。
6. **参数收口**：`max_tokens`、`betas`、`thinking`、`metadata`、`context_management` 一起进对象（[`claude.ts:1715`](../annotated/src/services/api/claude.ts#L2321)），最后 `create({...params, stream: true})`（[`claude.ts:1822`](../annotated/src/services/api/claude.ts#L2493)）。

`max_tokens` 不是写死的 8K/32K：`getMaxOutputTokensForModel()` 先取模型原生上限，再在开关 `tengu_otk_slot_v1` 打开时压到 `CAPPED_DEFAULT_MAX_TOKENS`，最后让 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` 覆盖（[`claude.ts:3399`](../annotated/src/services/api/claude.ts#L4635)）。注释给了理由：BQ p99 实际输出 4,911 token，32K/64K 默认值会多预留 8–16 倍槽位。

### 容错是两层，不是一层

第一层 `withRetry`：`DEFAULT_MAX_RETRIES = 10`、`MAX_529_RETRIES = 3`、`BASE_DELAY_MS = 500`（[`withRetry.ts:52`](../annotated/src/services/api/withRetry.ts#L105)）。退避公式是 `min(500 × 2^(attempt−1), 32000)` 再加 0–25% 抖动（[`withRetry.ts:530`](../annotated/src/services/api/withRetry.ts#L909)）。10 次重试的等待上限实算：

```bash
python -c "print(sum(min(500*2**i, 32000) for i in range(10)))"
# 159500  → 基准 159.5 秒；加满抖动约 199 秒
```

关键细节：SDK 自带重试被显式关掉——`getAnthropicClient({ maxRetries: 0 })`，注释写「Disabled auto-retry in favor of manual implementation」（[`claude.ts:1781`](../annotated/src/services/api/claude.ts#L2427)）。只有一套重试逻辑，才不会出现「SDK 重试 3 次 × 外层再重试 10 次」的乘法。

第二层 `errors.ts`：`getAssistantMessageFromError()` 有 **34 个 `return createAssistantAPIErrorMessage(...)` 分支**（`awk` 实测，函数体 `errors.ts:425-934`）。它**不抛**，而是把超时、限流、额度不足、PDF 过大等分别翻译成一条 assistant 消息，主循环照常往下走。分类常量集中在文件头（[`errors.ts:54`](../annotated/src/services/api/errors.ts#L81)）。

## 7.4 ② MCP：把外部进程的工具变成自己的工具

**MCP = Model Context Protocol（模型上下文协议）**。一句话：它规定「AI 客户端」和「工具服务器」之间怎么用 JSON-RPC 互相发现和调用。CC 既是 MCP 客户端（连别人的工具），也能当 MCP 服务器（`claude mcp serve`，见 01 篇）。

| 文件 | 行数 | 在整条链路的哪一格 |
| --- | ---: | --- |
| [`mcp/client.ts`](../annotated/src/services/mcp/client.ts#L932) | 3,348 | **连接 + 发现 + 调用**：传输握手、`tools/list`、结果转换 |
| [`mcp/config.ts`](../annotated/src/services/mcp/config.ts#L2372) | 1,578 | **配置汇总**：把七种来源合并成「要连哪些服务器」 |
| [`mcp/auth.ts`](../annotated/src/services/mcp/auth.ts) | 2,465 | **授权**：远程 MCP 的 OAuth / XAA |

### 从配置到一次工具调用，五步

1. **配置有七种范围**，不是三种：`local / user / project / dynamic / enterprise / claudeai / managed`（[`mcp/types.ts:20`](../annotated/src/services/mcp/types.ts#L29)）。
2. **传输有六种**：`stdio / sse / sse-ide / http / ws / sdk`（[`mcp/types.ts:29`](../annotated/src/services/mcp/types.ts#L29)）。`stdio` 分支就是起一个子进程，`stderr: 'pipe'` 防止服务器日志污染界面（[`client.ts:950`](../annotated/src/services/mcp/client.ts#L1449)）。
3. **连接被缓存**：`connectToServer` 用 `memoize` 包住（[`client.ts:595`](../annotated/src/services/mcp/client.ts#L932)），同名服务器不会重复握手。
4. **工具发现**：向服务器发 `{ method: 'tools/list' }`（[`client.ts:1752`](../annotated/src/services/mcp/client.ts#L2580)），拿回名字、描述、`inputSchema`、`annotations`。
5. **变成 CC 的 `Tool`**：名字统一成 `mcp__<server>__<tool>`（[`mcpStringUtils.ts:39`](../annotated/src/services/mcp/mcpStringUtils.ts#L57)），`readOnlyHint` 直接映射成 `isConcurrencySafe()` / `isReadOnly()`（[`client.ts:1795`](../annotated/src/services/mcp/client.ts#L2580)）。

### 超时数字很反常，但都是真的

- **单次 HTTP 请求** 60 秒：`MCP_REQUEST_TIMEOUT_MS = 60000`（[`client.ts:463`](../annotated/src/services/mcp/client.ts#L701)）。GET 故意不设超时，因为 MCP 的 GET 是长期 SSE 流。
- **工具调用**默认 **100,000,000 ms ≈ 27.8 小时**：`DEFAULT_MCP_TOOL_TIMEOUT_MS`（[`client.ts:211`](../annotated/src/services/mcp/client.ts#L321)）。理由是外部工具可能跑很久，宁可让用户按取消，也不擅自判死。
- **连接握手**另有 `getConnectionTimeoutMs()`，超时会主动 `transport.close()` 再 reject（[`client.ts:1049`](../annotated/src/services/mcp/client.ts#L1608)）。

```bash
grep -n "DEFAULT_MCP_TOOL_TIMEOUT_MS =\|MCP_REQUEST_TIMEOUT_MS =" source/src/services/mcp/client.ts
# 211:const DEFAULT_MCP_TOOL_TIMEOUT_MS = 100_000_000
# 463:const MCP_REQUEST_TIMEOUT_MS = 60000
```

## 7.5 ③ LSP：编辑器功能为什么要借语言服务器

**LSP = Language Server Protocol（语言服务器协议）**。TypeScript 的「跳转定义」「红波浪线」不是字符串匹配能做出来的，背后是一个真正跑类型检查的进程。CC 不自己实现这些，它**只当客户端**，把 VS Code 那套协议复用过来。

| 文件 | 行数 | 在整条链路的哪一格 |
| --- | ---: | --- |
| [`LSPServerManager.ts`](../annotated/src/services/lsp/LSPServerManager.ts#L16) | 420 | **路由**：按文件扩展名找该用哪个服务器，负责 `didOpen/didChange/didSave/didClose` |
| [`LSPClient.ts`](../annotated/src/services/lsp/LSPClient.ts) | 447 | **协议**：`initialize` 能力协商、JSON-RPC 请求/通知 |
| [`passiveFeedback.ts`](../annotated/src/services/lsp/passiveFeedback.ts#L92) | 328 | **回灌**：把 `publishDiagnostics` 通知转成附件，下一轮自动进上下文 |

### 服务器从哪来：只认插件

`getAllLspServers()` 的注释写得很直白：「LSP servers are only supported via plugins, not user/project settings.」（[`lsp/config.ts:11`](../annotated/src/services/lsp/config.ts#L11)）。它并行读所有已启用插件，单个插件抛错只记日志，不影响其他插件（[`lsp/config.ts:69`](../annotated/src/services/lsp/config.ts#L130)）。

### 诊断怎么变成「AI 自己会看报错」

```
插件声明服务器 → manager 异步初始化（不阻塞启动）
   → 按扩展名路由 → didOpen/didChange 同步文件
      → 服务器推 publishDiagnostics
         → LSPDiagnosticRegistry 暂存（每文件 ≤10 条、全局 ≤30 条）
            → 下一轮 query 开头作为 attachment 注入（utils/attachments.ts:2896）
```

三个工程细节：

- **单例 + 代次计数**：`initializationGeneration` 防止「迟到的旧初始化」覆盖新状态（[`manager.ts:14`](../annotated/src/services/lsp/manager.ts#L27)）。
- **限流**：`MAX_DIAGNOSTICS_PER_FILE = 10`、`MAX_TOTAL_DIAGNOSTICS = 30`，跨轮去重用 500 项的 LRU（[`LSPDiagnosticRegistry.ts:44`](../annotated/src/services/lsp/LSPDiagnosticRegistry.ts#L62)）。不设上限，一次全项目报错就能把上下文塞爆。
- **优雅降级**：启动超时用 `Promise.race` 包住并在 `finally` 清定时器（[`LSPServerInstance.ts:497`](../annotated/src/services/lsp/LSPServerInstance.ts#L660)）；关停失败只记日志（[`manager.ts:278`](../annotated/src/services/lsp/manager.ts#L406)）。

## 7.6 ④ 账号与认证：OAuth 的五个数

| 文件 | 行数 | 在整条链路的哪一格 |
| --- | ---: | --- |
| [`oauth/client.ts`](../annotated/src/services/oauth/client.ts#L90) | 566 | **协议主体**：拼授权 URL、换 token、刷新 token、查过期 |
| [`oauth/auth-code-listener.ts`](../annotated/src/services/oauth/auth-code-listener.ts#L254) | 211 | **回调**：本地起 HTTP 服务器接 `?code=` |
| [`oauth/crypto.ts`](../annotated/src/services/oauth/crypto.ts#L78) | 23 | **PKCE**：verifier / challenge / state 三个随机值 |

流程五步，每步都有可验证的数字：

1. **生成 verifier**：`randomBytes(32)` 再做 base64url（[`crypto.ts:11`](../annotated/src/services/oauth/crypto.ts#L58)）。
2. **算 challenge**：`SHA-256(verifier)` 后 base64url，方法写死 `S256`（[`client.ts:86`](../annotated/src/services/oauth/client.ts#L158)）。
3. **本地收码**：监听 `localhost:0`（端口交给操作系统分配），避免固定端口冲突（[`auth-code-listener.ts:46`](../annotated/src/services/oauth/auth-code-listener.ts#L95)）。
4. **校验 state**：回调里的 `state` 与发起时保存的不一致就 `reject`，防 CSRF（[`auth-code-listener.ts:164`](../annotated/src/services/oauth/auth-code-listener.ts#L254)）。
5. **换 token / 续期**：`exchangeCodeForTokens()` 带 `code_verifier`（[`client.ts:107`](../annotated/src/services/oauth/client.ts#L191)）；过期判断**提前 5 分钟**：`expiresAt - now <= 5 × 60 × 1000` 就算过期（[`client.ts:344`](../annotated/src/services/oauth/client.ts#L490)）。

提前 5 分钟是「续期窗口」不是「过期时间」：请求发到一半 token 失效，比提前刷新代价大得多。`OAuthService` 把这几步包成一个类，调用方只有 `cli/handlers/auth.ts`、`components/ConsoleOAuthFlow.tsx` 等少数入口（[`oauth/index.ts:21`](../annotated/src/services/oauth/index.ts#L44)）。

## 7.7 ⑤ 埋点与统计：1,092 个调用点怎么不拖慢启动

| 文件 | 行数 | 在整条链路的哪一格 |
| --- | ---: | --- |
| [`analytics/index.ts`](../annotated/src/services/analytics/index.ts#L28) | 173 | **门面**：零依赖、事件先入队、只暴露 `logEvent` |
| [`analytics/sink.ts`](../annotated/src/services/analytics/sink.ts#L70) | 114 | **路由**：采样、Datadog 开关、剥离 `_PROTO_*` |
| [`analytics/growthbook.ts`](../annotated/src/services/analytics/growthbook.ts#L791) | 1,155 | **运行时开关**：`getFeatureValue_CACHED_MAY_BE_STALE()` |

全仓 `logEvent(` 实际调用 **1,092 处**（已排除 1 处函数定义），字面量事件名 **660 个**（`grep -rn "logEvent(" source/src | grep -v "function logEvent" | wc -l`、`grep -rho "logEvent('[a-z0-9_]*'" | sort -u | wc -l`）。密度这么高，门面必须便宜：

- **零依赖 + 队列**：sink 没挂上前，事件进 `eventQueue`；`attachAnalyticsSink()` 用 `queueMicrotask` 异步排空，不阻塞启动（[`index.ts:95`](../annotated/src/services/analytics/index.ts#L124)）。
- **编译期隐私门**：`AnalyticsMetadata_I_VERIFIED_THIS_IS_NOT_CODE_OR_FILEPATHS = never`（[`index.ts:19`](../annotated/src/services/analytics/index.ts#L28)）。想把字符串塞进埋点，必须显式 `as` 这个类型，等于在代码里签名「我确认这不是代码/路径」。
- **PII 双通道**：`_PROTO_*` 字段在 Datadog 分发前被 `stripProtoFields()` 删掉，只有 1P exporter 能看到并写入受控列（[`sink.ts:64`](../annotated/src/services/analytics/sink.ts#L70)）。
- **熔断开关**：`isSinkKilled('datadog')` 一旦为真，直接不发（`sink.ts:30`）。

**成本统计不在这里**：它由 [`cost-tracker.ts`](../source/src/cost-tracker.ts#L228)（323 行）负责，但输入来自 API 层——每收到一段流式用量，`calculateUSDCost()` 算钱后调 `addToTotalSessionCost()`（[`claude.ts:2251`](../annotated/src/services/api/claude.ts#L3101)）。所以「埋点」和「计费」是两条线：前者进 Datadog/1P，后者进本地会话账本与 `/cost`。

## 7.10 服务层的三条通用约定

这三条不是「设计模式课」，是能在源码里指到具体行的工程约束。

### 约定一：依赖注入，服务是「可替换零件」

主循环不直接 import 具体实现，而是收一个 `deps`：

```ts
// source/src/query/deps.ts:21-31（略去注释）
export type QueryDeps = {
  callModel: typeof queryModelWithStreaming
  microcompact: typeof microcompactMessages
  autocompact: typeof autoCompactIfNeeded
  uuid: () => string
}
```

调用点 `const deps = params.deps ?? productionDeps()`（[`query.ts:263`](../annotated/src/query.ts#L521)）。注释说范围「故意只有 4 个，先证明模式」，测试可以注入假函数，不必 `spyOn` 整个模块。这就是服务层最干净的一条边界：**上层依赖接口，不依赖文件路径**。

### 约定二：错误到边界就「降级」，不穿透到 UI

服务层不是全都 never-throw，但**可选能力**一律降级：

- LSP 加载失败：`catch` 后返回空表，注释原话「LSP is optional, so we don't throw」（[`lsp/config.ts:69`](../annotated/src/services/lsp/config.ts#L130)）。
- 埋点开关查询失败：`catch { return false }`，没有埋点也要能启动（[`sink.ts:39`](../annotated/src/services/analytics/sink.ts#L53)）。
- API 异常：转成 `AssistantMessage` 返回，函数签名就是 `: AssistantMessage` 而不是 `throws`（[`errors.ts:425`](../annotated/src/services/api/errors.ts#L557)）。
- 需要区分「失败」与「空值」时用显式结果类型：`ApiResult<T> = { success: true; data: T } | { success: false }`（[`grove.ts:42`](../annotated/src/services/api/grove.ts#L72)）。

判断标准很简单：**这个能力挂了，主流程还能不能继续**。能，就降级；不能（比如鉴权失败），才抛。

### 约定三：超时与取消必须成对出现

- 取消：`withRetry` 每轮开头查 `options.signal?.aborted`，已取消就抛 `APIUserAbortError`（[`withRetry.ts:191`](../annotated/src/services/api/withRetry.ts#L390)）；所有 `sleep()` 都带 signal，睡到一半取消能立刻醒（`withRetry.ts:511`）。
- 请求超时：非流式回退默认 **300 秒**（远程 120 秒），可用 `API_TIMEOUT_MS` 覆盖（[`claude.ts:807`](../annotated/src/services/api/claude.ts#L1028)）。
- 流式空闲超时：**90 秒**没收到任何 chunk 就 abort，并有 45 秒的预警（[`claude.ts:1877`](../annotated/src/services/api/claude.ts#L2571)）。
- 外部工具超时：MCP 单请求 60 秒、工具调用默认 100,000,000 ms（7.4 已给行号）。
- 启动超时：LSP 用 `Promise.race` + `finally clearTimeout`，避免留下孤儿定时器（[`LSPServerInstance.ts:497`](../annotated/src/services/lsp/LSPServerInstance.ts#L660)）。

反面教材也在源码里：`wrapFetchWithTimeout()` 特意不用 `AbortSignal.timeout()`，因为 Bun 下它的内部定时器要等 GC 才释放，每个请求会残留约 2.4KB 原生内存（[`client.ts:512`](../annotated/src/services/mcp/client.ts#L788)）。**超时不是设个数字就完了，定时器要有归属。**

## 7.11 常见误读

| ❌ 0 基础最可能这样读 | ✅ 实际是什么 |
| --- | --- |
| `services/` 是一组「后端微服务」 | 全是**进程内模块**，没有独立服务进程；唯一的外部进程是 MCP 的 stdio 子进程 |
| `analytics/` 只负责发埋点 | 还负责采样、Datadog 灰度开关、PII 分流、紧急熔断，以及 GrowthBook 运行时开关 |
| MCP 只有 4 种传输 | 类型定义里有 **6 种**：`stdio / sse / sse-ide / http / ws / sdk` |
| LSP 是 CC 自己实现的补全 | CC 只实现**客户端**；语言服务器全部来自插件，配置也只认插件 |
| OAuth 就是「登录一次」 | 还有 PKCE、state 防 CSRF、提前 5 分钟判过期、refresh token 续期 |
| 服务层出错都会往上抛 | 可选能力在边界降级（空表 / false / 错误消息），只有主流程不可缺的才抛 |

## 7.12 本篇小结

- 服务层 **130 文件 53,683 行**，20 个子目录；`mcp/` + `api/` 占 42.4%，前五块占 66.5%。
- `api/` 一次请求六步：工具表 → 消息归一化 → 配对修复 → 系统提示分块 → 缓存断点 → 参数收口；SDK 重试被关掉，只留外层 `withRetry`。
- `mcp/` 的本质是「配置 → 连接 → `tools/list` → 改名 `mcp__server__tool` → 当普通 Tool 调用」，超时数字反常但都有注释。
- `lsp/` 只当客户端，价值在 `passiveFeedback`：诊断自动变成下一轮附件，且每文件 10 条、全局 30 条限流。
- `oauth/` 五个数：32 字节 verifier、S256、state、5 分钟提前过期、本地 0 号端口。
- `analytics/` 用零依赖 + 队列 + 品牌类型，扛住 1,092 个调用点；成本统计在 `cost-tracker.ts`，不在 services。
