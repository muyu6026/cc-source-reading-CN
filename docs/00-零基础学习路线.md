# 零基础学习路线（六层 · 一个单元 30 分钟）

> **写给谁**：没写过 TypeScript、没读过上千行的文件、看见满屏英文注释就想关掉的人。
> **和旧路线的分工**：旧「七步」是按**模块**切的（一步 = 半天 = 几百到七千行），适合有基础的人查资料；这份是按**你能读懂的最小单位**切的（一单元 = 20–30 分钟 = 2–150 行），适合从零开始一关一关过。

---

## 0. 先说清楚：旧路线为什么第一步就会卡住

旧的第 1 步是「读 `cli.tsx` 前 120 行」。对一个没写过 TS 的人，这 120 行里同时出现了：

| 你会撞到的东西 | 它在第 1 步就出现 | 为什么当时没解释 |
| --- | --- | --- |
| 动态 `import()`（函数式导入） | 是 | 属于模块系统进阶 |
| `feature('XXX')` 构建期开关 | 是 | 属于打包工具知识 |
| `process.argv` 进程参数 | 是 | 属于 Node 运行时知识 |
| `.js` 后缀但文件是 `.ts` | 是 | 属于 TS 编译约定 |

这四样任何一样没搞懂，读下去就只是「眼睛扫过文字」，不会有理解。**不是你的问题，是顺序的问题。**

| | 旧路线 | 这份路线 |
| --- | --- | --- |
| 一步多大 | 一个模块（500–7,537 行） | 一个单元（2–150 行） |
| 一步多久 | 半天到一天 | 20–30 分钟 |
| 第一步读什么 | `cli.tsx`（120 行，四个未解释的概念） | `commands/clear/index.ts`（19 行，六个字段） |
| 读完怎么知道懂了 | 没有验收 | 3 个问题 + 1 个验证动作 |
| 前置知识 | 默认你会 TypeScript | L0 从零补，每个语法配真实代码 |
| 遇到不懂的 | 自己扛 | 每单元标了「前置」，缺什么回哪节补 |

### L0-8 `async` / `await`：0 基础最大的坎

> 📖 **精读版已上线**：本课时已扩写成独立文档（逐行拆解 + 完整解答 + 自测）→ [`L0-08-async与await.md`](L0/L0-08-async与await.md)**⏱ 40 分钟｜📄 15 行｜前置：L0-7**

读：[`annotated/src/commands/clear/clear.ts`](../annotated/src/commands/clear/clear.ts) 全 7 行

```ts
export const call: LocalCommandCall = async (_, context) => {
  await clearConversation(context)
  return { type: 'text', value: '' }
}
```

**一句话**：`async` 标记「这个函数要等别人」，`await` 标记「这里要等结果，等到了再往下走」。**没有 `await` 的那一行，会在结果还没回来时就先执行**。

**带三个问题读**
1. 第 4 行的 `_` 是什么？（一个「我不打算用」的参数，下划线是约定）
2. 把第 5 行的 `await` 删掉会发生什么？（清理还没做完就返回了）
3. `async` 函数一定返回 `Promise` 吗？（一定。所以调用它的人也得 `await`）

**读完自测**：用自己的话说清「`async` 标注的是函数的什么性质」。

**验证**：`grep -rn "async" source/src/commands/clear/clear.ts source/src/commands/clear/conversation.ts | head -3`

### L0-9 三个最容易读错的符号：`?.`　`??`　`!`

> 📖 **精读版已上线**：本课时已扩写成独立文档（逐行拆解 + 完整解答 + 自测）→ [`L0-09-三个易错符号.md`](L0/L0-09-三个易错符号.md)**⏱ 30 分钟｜📄 5 行｜前置：L0-5**

读三处真实代码：

| 写法 | 位置 | 什么意思 |
| --- | --- | --- |
| `clock?.now() ?? 0` | [`src/ink/hooks/use-interval.ts`](../source/src/ink/hooks/use-interval.ts) 第 15 行 | `clock` 可能是空 → 空就别调 `now()`，整个表达式变 `undefined`；再用 `0` 兜底 |
| `errorMessage?.includes(...)` | [`src/tools/GlobTool/UI.tsx`](../source/src/tools/GlobTool/UI.tsx) 第 40 行 | 没报错信息就跳过，不崩 |
| `result1!.updatedFile` | [`src/tools/FileEditTool/utils.ts`](../source/src/tools/FileEditTool/utils.ts) 第 725 行 | 我保证它不是空，别报错（**这是一个「我不想检查」的声明**） |

**一句话**：`?.` 是「空了就停，别崩」，`??` 是「空了就用后面这个」，`!` 是「我发誓它不空，出事我负责」。

**带三个问题读**
1. `??` 和 `||` 有什么区别？（`0` 和 `''` 用 `??` 会保留，用 `||` 会被替换掉）
2. `!` 写错了会怎样？（编译不报错，运行时炸——这是本仓库 0 基础最容易误用的符号）
3. 为什么本仓库到处是 `?.`？（数据来自网络/文件/用户输入，任何一处都可能是空）

**读完自测**：`a?.b ?? c` 用一句中文念出来。

**验证**：`grep -rn "?? 0" source/src/ink/hooks/use-interval.ts`

### L0-11 为什么 `import` 写 `.js` 但文件是 `.ts`

实际文件：          source/src/commands.ts   ← 磁盘上是 .ts
```

**一句话**：TypeScript 编译成 JavaScript 之后，文件扩展名会变成 `.js`。为了让**编译后的产物**能正确找到文件，import 路径必须写最终形态（`.js`）。这是 ES Module 的硬性要求，不是笔误。

**带三个问题读**
1. 如果写成 `'../../commands'`（不带后缀）行不行？（本仓库不行，ESM 要求写全）
2. 为什么第 16 行 `import('./clear.js')` 也写 `.js`？
3. 你在文件里搜索时，该搜 `.ts` 还是 `.js`？（找文件搜 `.ts`，找引用搜 `.js`）

**读完自测**：解释「为什么写 `.js` 的文件在磁盘上叫 `.ts`」，讲给一个没学过 TS 的人听。

**验证**：`ls source/src/commands.ts && grep -n "commands.js" source/src/commands/clear/index.ts`

  → 权限怎么判？判几次？
  → 谁真正读磁盘？
  → 结果怎么变成一条 tool_result？
  → tool_result 怎么回到消息历史？
  → 下一次请求它长什么样？
```

## 9. 每个单元的固定版式（怎么用这份地图）

每个单元都是同一个结构，照着做就行：

| 部分 | 你该做什么 |
| --- | --- |
| **⏱ 时长｜📄 行数｜前置** | 超时就先停，别硬撑；前置没读先回去补 |
| **读** | 只读标出来的那几行/那个文件，**不要顺手往下翻** |
| **一句话** | 先看这句，建立预期——知道要找什么，眼睛才找得到 |
| **带三个问题读** | 带着问题读，比通读快 5 倍。答不出就是没读懂 |
| **读完自测** | **合上文件**再答。开着文件答等于抄 |
| **验证** | 跑那条命令，用输出确认「我以为的」和「代码里的」一致 |

> 一天最多 4 个单元。超过就是「扫过」不是「读过」。
