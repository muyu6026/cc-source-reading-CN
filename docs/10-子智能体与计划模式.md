## 10.1 子智能体：让 AI 派 AI 去干活

> 📁 本节源码：[`src/tools/AgentTool/runAgent.ts:1-21`](../source/src/tools/AgentTool/runAgent.ts#L1-L21)

`AgentTool` 让你（或主 Agent）**再开一个 Agent 去干子任务**。

它的实现 `runAgent.ts` 本质上就是**递归地再调一次 `query()`**：

```ts
// src/tools/AgentTool/runAgent.ts:1-21（顶部 import 节选，query 在第 15 行）
import { query } from '../../query.js'          // ← 复用主对话循环
import { connectToServer, fetchToolsForClient } from '../../services/mcp/client.js'
import type { AssistantMessage, Message, UserMessage } from '../../types/message.js'
// …子智能体有自己独立的消息历史、工具集、模型，跑完把结果回传给父 Agent
```

### 为什么是"递归调 query()"
回忆 [06 篇](06-对话主循环与模型调用.md)：`query()` 就是那个 `while(true)` 循环。

```
父 Agent 的 query() 循环
   ↓ 模型说"我要调 AgentTool"
   ↓
AgentTool 执行 → runAgent()
   ↓
再调一次 query()  ← 子 Agent 也有自己的 while(true) 循环
   ↓
子 Agent 跑完，把结果 return 给父 Agent
   ↓
父 Agent 把结果当 tool_result 塞回自己的 messages，继续循环
```

**这就是"递归"的含义**：不是另写一套调度系统，而是**同一个 `query()` 函数再跑一遍**，只是换了消息历史和工具集。

### 子智能体的文件分工
| 文件 / 目录 | 作用 |
|-------------|------|
| `runAgent.ts` | 子智能体运行时（递归 `query()`） |
| `built-in/` + `builtInAgents.ts` | 内置子智能体（如 `Explore` 探索型、`Plan` 规划型） |
| `agentMemory.ts` / `agentMemorySnapshot.ts` | 子智能体的记忆 |
| `forkSubagent.ts` | 派生子进程式子智能体 |
| `loadAgentsDir.ts` | 加载用户自定义的 agent 定义 |

### 子智能体和主 Agent 的区别
| 维度 | 主 Agent | 子智能体 |
|------|----------|----------|
| 消息历史 | 你的完整对话 | **独立**，只看得到被交代的任务 |
| 工具集 | 全部工具 | 可能被裁剪（如只给读工具） |
| 模型 | 当前选的模型 | 可以指定更便宜 / 更强的模型 |
| 上下文 | 共享主对话 | 隔离，跑完只回传结果 |

> **为什么要隔离上下文？** 因为子任务常常会产生大量"中间过程"（读了一堆文件、跑了一堆命令）。如果全塞回主对话，主上下文很快就爆了。隔离后，**只把最终结论回传**，主对话保持干净。

## 10.2 计划模式：先想清楚再动手
对应你在界面上看到的"先规划后执行"工作流。

| 工具 | 作用 |
|------|------|
| `src/tools/EnterPlanModeTool/` | 进入计划模式（权限模式切到 `plan`，只能看 / 想，不能改） |
| `src/tools/ExitPlanModeTool/` | 退出计划模式（把你审过的方案交回去执行） |

每个工具目录结构都和 `BashTool` 类似：

```
EnterPlanModeTool/
├── EnterPlanModeTool.ts   ← 逻辑
├── UI.tsx                 ← 界面
├── constants.ts           ← 常量
└── prompt.ts              ← 给模型的英文指令
```

### 计划模式和权限模式的关系
`plan` 本身就是 [08 篇](08-权限与安全.md)里的六种权限模式之一。进入计划模式 = **把权限模式切到 `plan`**：

```
用户：/plan 或模型调 EnterPlanModeTool
   ↓
权限模式 = 'plan'
   ↓
此时 hasPermissionsToUseTool() 会拒绝一切"写"操作
（改文件 / 跑命令 → deny）
   ↓
模型只能"读 + 想"，产出一份方案
   ↓
用户审方案 → 同意
   ↓
ExitPlanModeTool 或用户切回 'default'
   ↓
权限模式恢复，开始真正执行
```

> 这个设计的妙处：**不需要单独写一套"禁止修改"的逻辑**，直接复用权限系统的 `plan` 模式。一套机制，两处用途。

## 10.3 `prompt.ts` 里的英文指令（值得中英对照读）

> 📁 本节源码：[`src/tools/AgentTool/prompt.ts`](../source/src/tools/AgentTool/prompt.ts)

每个工具目录下的 `prompt.ts` 是"告诉模型这个工具该怎么用"的英文指令。

以计划模式为例，`prompt.ts` 大致会告诉模型：

- 在计划模式里，你**只能调研和思考**，不能修改任何东西；
- 你的产出应该是一份**清晰的执行计划**；
- 计划要具体到"改哪个文件、做什么改动"，让用户能审阅。

> **学习要点**：`prompt.ts` 是 prompt 工程的一手教材。它示范了"如何用一段英文把工具的使用边界、输出格式、禁止事项讲清楚"。建议把 `EnterPlanModeTool/prompt.ts` 和 `BashTool/prompt.ts` 对照读——前者教"约束行为"，后者教"描述参数"。

## 10.4 三层"AI 派 AI"的演进
| 层级 | 机制 | 源码 |
|------|------|------|
| 第 1 层 | 单个 Agent 循环调工具 | `query.ts` 的 `while(true)` |
| 第 2 层 | Agent 派子 Agent（递归 query） | `tools/AgentTool/runAgent.ts` |
| 第 3 层 | 协调器调度多个 worker（多智能体编排） | `src/coordinator/`、`TeamCreateTool` |

> 理解顺序也是这个顺序：先看懂第 1 层（06 篇），第 2 层（本篇）自然就懂了，第 3 层只是在此之上加了"团队管理"。

## 10.5 本篇小结
- 子智能体 = **递归再调一次 `query()`**，不是另写一套系统。
- 子智能体有**独立的消息历史、工具集、模型**，只把结果回传父 Agent——这是为了**省主上下文**。
- 计划模式 = **权限模式切到 `plan`**，复用权限系统，不另写逻辑。
- 三层演进：单 Agent 循环 → 子 Agent 递归 → 协调器多智能体。
