## 1. 精读正文

全文件 9 行，逐字摘录：

```ts
1 │ import { logForDebugging } from '../utils/debug.js'
2 │
3 │ export function ifNotInteger(value: number | undefined, name: string): void {
4 │   if (value === undefined) return
5 │   if (Number.isInteger(value)) return
6 │   logForDebugging(`${name} should be an integer, got ${value}`, {
7 │     level: 'warn',
8 │   })
9 │ }
```

### 1.1 第 1 行：函数唯一的外部依赖

```ts
1 │ import { logForDebugging } from '../utils/debug.js'
```

具名导入一个「记调试日志」的函数。**中文念法**：「从上一级目录的 `utils/debug.js` 里，拿一个叫 `logForDebugging` 的函数。」注意路径 `../` 往上跳一级——本文件住在 `src/ink/`，所以这是 `src/utils/debug.js`。

### 1.2 第 3 行：函数签名，把「收什么」说死

```ts
3 │ export function ifNotInteger(value: number | undefined, name: string): void {
```

逐段拆：

- **`export function`** —— 导出一个函数（L0-03 讲过 `export`；这里是具名导出，不是 `default`）。
- **`ifNotInteger`** —— 函数名，直译「如果不是整数（就报警）」。名字本身就是文档：**读函数名就知道它干什么**。
- **`value: number | undefined`** —— 第一个参数叫 `value`，类型是「`number` 或 `undefined`」（联合类型，L0-06 讲过 `|` 读作「或」）。这个类型**精确描述了现实**：调的人可能传一个数字，也可能什么都不传。
- **`name: string`** —— 第二个参数是字符串，这是「出问题时该怪哪个字段」的名字，比如 `'margin'`。
- **`: void`** —— 返回值类型是 `void`：「这个函数**不返回任何东西**」。它做事的方式是「报警」这一副作用，不产出结果。

**中文念法**：

> 「导出函数 `ifNotInteger`：收一个可能是数字也可能是 `undefined` 的 `value`，和一个叫 `name` 的字符串；不返回东西。」

### 1.3 第 4–5 行：两次早返回

```ts
4 │   if (value === undefined) return
5 │   if (Number.isInteger(value)) return
```

- **第 4 行**：`value === undefined` 用三个等号做严格比较（L0-09 讲过 `===` 不做类型转换）。若 `value` 压根没传，**直接 `return`**——没传就不是错误，不报警。注意 `return` 后面什么都不带，配合返回类型 `void`，意思就是「到此为止，函数结束」。
- **第 5 行**：`Number.isInteger(value)` 是内置方法，判断「是不是整数」（`5` 是、`5.5` 不是、`NaN` 和 `Infinity` 都不是）。是整数 → 正常情况 → 也直接 `return`。

**「早返回」的形状**：函数一路往下走，每遇到一个「不需要处理」的情形就提前退出。走到底还活着的，只剩「该报警」的那一种。对比 `if/else` 嵌套写法：

```ts
// 不用早返回的等价写法（没人这么写，因为难读）：
if (value === undefined) {
  // 什么都不做
} else if (Number.isInteger(value)) {
  // 什么都不做
} else {
  logForDebugging(...)
}
```

处理逻辑被压进最深的缩进层，而早返回版本**每多一层缩进，人脑就多背一层上下文**——早返回把嵌套拉直成直线。

### 1.4 第 6–8 行：真正干活的报警 + 模板字符串

```ts
6 │   logForDebugging(`${name} should be an integer, got ${value}`, {
7 │     level: 'warn',
8 │   })
```

重点看第 6 行那对**反引号**（`` ` ``，键盘左上角）。反引号包起来的叫**模板字符串**，它比普通单引号字符串多一个能力：`${}` 里可以放**任何表达式**，求值后嵌进文本。这叫**插值**。

- `${name}` —— 把第二个参数的值嵌进去，比如 `'margin'`；
- `${value}` —— 把第一个参数的值嵌进去，比如 `0.5`；
- 于是 `ifNotInteger(0.5, 'margin')` 最终拼出：`margin should be an integer, got 0.5`。

**中文念法**：

> 「报警文本 = name 的值 + ` should be an integer, got ` + value 的值。」

第 7 行 `level: 'warn'` 是第二个参数——一个对象字面量，指明日志级别是「警告」。这里埋着全仓的一条纪律（见讲义 §2.10）：**中文批注绝不能插进反引号内部**，否则中文会变成程序真的输出的一部分。

### 1.5 谁在用它（实测）

- `source/src/ink/components/Box.tsx` 第 10 行 `import * as warn from '../warn.js'`，第 110–126 行对 `margin`、`padding`、`gap` 等 **17 个布局字段**挨个调用 `warn.ifNotInteger(...)`；
- `source/src/ink/screen.ts` 第 13 行同样以 `import * as warn` 导入，第 459–460 行校验屏幕宽高。

## 2. 核心问题（路线卡片原题的完整解答）

### 2.1 两个 `if` 的顺序能不能换？

这是本课的思考题，答案要靠推理，不能靠感觉。先建立事实：

**`Number.isInteger(undefined)` 的返回值是 `false`。** `isInteger` 只对「真的是整数的数字」返回 `true`；`undefined` 不是数字，直接返回 `false`，也不会抛错。

现在把两行对调，逐种取值推演：

| value 取值 | 换后第 1 步 `if (Number.isInteger(value)) return` | 换后第 2 步 `if (value === undefined) return` | 最终结果 | 与原顺序比 |
| --- | --- | --- | --- | --- |
| `undefined` | `isInteger(undefined)` = `false`，不返回 | 命中，返回 | 静默结束 | 相同 |
| `5` | `true`，返回 | （走不到） | 静默结束 | 相同 |
| `0.5` | `false`，不返回 | 不命中 | 走到报警 | 相同 |

**结论：行为上可以换**——交换后对每种输入的结果都与原来完全一致，关键正是 `isInteger(undefined)` 是 `false`：`undefined` 不会在第一个 `if` 处被误当成「正常值」放过去（如果它返回 `true`，对调后 `undefined` 就会被当成整数静默放行，报警永远不触发，那才是真 bug）。

**那为什么还保持现在的顺序？** 两点：

1. **可读性分层**。先判「参数来没来」（缺失），再判「值好不好」（合法），是早返回的惯例层次——先排除结构性缺失，再做业务判断。
2. **防将来改动**。如果日后有人把第一个 `if` 改成别的缺失判断（或往中间插新的检查），「缺失优先」的固定次序能让每一次修改的推理都更简单。

顺带说明批注版里的注解「两个提前返回的顺序有意义」：它强调的是**语义分层**——`undefined` 的含义是「没写就是没写，不是错误」（L1 教材批注原文），这个层次要在阅读时先看清；就纯行为而言，如上推理，两行可以互换。

### 2.2 `${name}` 这个写法是什么？

**模板字符串插值**（讲义 §2.10）。反引号 `` ` `` 内的 `${表达式}` 会被求值并拼进字符串。它和字符串拼接 `name + ' should be...'` 等价，但可读性好得多：整句保持原样，变量嵌在句子里一眼可见。`${}` 里能放任何表达式——本课是变量，别的文件里还有函数调用、三元运算等。

### 2.3 用一句中文说清 `ifNotInteger` 干了什么、什么时候什么都不干

> 「**校验一个布局数值是不是整数：没传，不管；是整数，不管；其余情形（小数、`NaN`、`Infinity`），往调试日志里写一条警告——但也不抛错、不返回值。**」

「什么都不干」的时刻就是两个早返回命中的时刻：`value === undefined`（没传）和 `Number.isInteger(value)` 为 `true`（是整数）。

## 3. 常见误读

**误读 1：以为 `return` 必须带一个值。**
返回类型是 `void` 的函数，`return` 后面什么都可以不带——它唯一的作用是「立刻结束本函数」。`if (x) return` 是早返回最常见的形式。

**误读 2：以为 `if (value === undefined) return` 会把「合法的 0」挡掉。**
`=== undefined` 只命中 `undefined`。数字 `0`、空字符串 `''` 都不是 `undefined`，会继续往下走。这正是坚持写 `=== undefined` 而不写 `if (!value)` 的原因——后者会把 `0` 误伤（L0-09 的假值陷阱）。

**误读 3：以为这个函数「发现错误」就该抛异常（throw）。**
它的设计决定恰恰相反：布局参数写错（比如终端里不存在的半格 `margin={0.5}`）只值得一条警告，不该让整个终端界面崩掉。**报警不抛错**是这个函数的核心选择，`void` 返回类型也暗示了「我只报告，不做决定」。

## 5. 合书自测

**1. `ifNotInteger(0.5, 'marginLeft')` 执行完后屏幕上会发生什么？**

<details>
<summary>参考答案</summary>

什么都不会立刻发生。函数走到报警行，把 `marginLeft should be an integer, got 0.5` 这条文本以 warn 级别写进调试日志；界面不崩、不返回任何值。

</details>

**2. 两个 `if` 的顺序能换吗？推理的关键在哪一步？**

<details>
<summary>参考答案</summary>

能换，行为不变。关键在 `Number.isInteger(undefined)` 返回 `false`——对调后 `undefined` 不会在第一个 `if` 被误判成整数放行，而是落到第二个 `if` 被拦下。保持现顺序的理由是「先排除缺失，再判断合法」的分层惯例。

</details>

**3. `value: number | undefined` 里的 `|` 是什么意思？**

<details>
<summary>参考答案</summary>

联合类型，读作「或」：`value` 可以是一个数字，也可以是 `undefined`（没传）。类型签名如实描述了调用方的两种可能。

</details>

**4. `` `${name} got ${value}` `` 里反引号和 `${}` 各起什么作用？**

<details>
<summary>参考答案</summary>

反引号声明这是模板字符串，允许嵌表达式；`${}` 是插值槽，里面的表达式求值后变成文本嵌入字符串。`name` 是 `'margin'`、`value` 是 `0.5` 时，结果是 `margin got 0.5`。

</details>

**5. `if (value === undefined)` 为什么不写成 `if (!value)`？**

<details>
<summary>参考答案</summary>

`!value` 对所有假值都命中，包括合法的 `0`——`margin: 0` 是完全正常的布局值，会被误挡。`=== undefined` 只命中「没传」这一种情形。

</details>
