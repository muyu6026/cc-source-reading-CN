> 对应源码：[`src/entrypoints/cli.tsx`](../source/src/entrypoints/cli.tsx)、[`src/main.tsx`](../source/src/main.tsx)、[`src/setup.ts`](../source/src/setup.ts)

---

## 3.1 第一棒：[`src/entrypoints/cli.tsx`](../source/src/entrypoints/cli.tsx)（真正的二进制入口）

> 📁 本节源码：[`src/entrypoints/cli.tsx`](../source/src/entrypoints/cli.tsx)

`package.json` 里 `"bin": { "claude": "cli.js" }` 指向的就是编译后的这个文件。

它的设计精髓：**所有重模块都用动态 import，只为让"快速路径"零加载**。

```ts
/**
 * Bootstrap entrypoint - checks for special flags before loading the full CLI.
 * 引导入口 —— 在加载完整 CLI 之前先检查特殊参数。
 * All imports are dynamic to minimize module evaluation for fast paths.
 * 所有 import 都是动态的，以最小化快速路径下的模块求值。
 * Fast-path for --version has zero imports beyond this file.
 * --version 的快速路径：除了本文件外零 import。
 */
async function main(): Promise<void> {
  const args = process.argv.slice(2)

  // Fast-path for --version/-v: zero module loading needed
  // 快速路径：--version 不需要加载任何模块
  if (args.length === 1 && (args[0] === '--version' || args[0] === '-v' || args[0] === '-V')) {
    console.log(`${MACRO.VERSION} (Claude Code)`)  // MACRO.VERSION 在构建时被内联
    return
  }
  // …后面根据参数分发到 bridge / daemon / remote-control / 或真正的 main()
}
```

### 这段代码在教什么
| 设计 | 好处 | 你以后可以怎么用 |
|------|------|------------------|
| 动态 `import()` | 只在需要时加载模块，启动更快 | 自己的 CLI 也可以给 `--version`、`--help` 做零加载快速路径 |
| `MACRO.VERSION` | 构建期把版本号直接替换成字符串 | 别在运行时读 `package.json`，构建时注入更省 |
| 参数分发 | 一个入口支持多种模式（bridge/daemon/remote） | 用"模式路由"而不是堆 if-else |

> **学习要点**：看大项目先找 `bin` 指向的文件，再看它怎么把活儿交给 `main.tsx`。这种"快速路径 + 动态 import"是性能优化标准套路。

## 3.2 第二棒：[`src/main.tsx`](../source/src/main.tsx) 的 `main()`

> 📁 本节源码：[`src/main.tsx`](../source/src/main.tsx)

`main()` 是一个 **800KB 级别**的巨型函数（约 4600 行），负责参数解析、各种 feature 分支，最终调用 `setup()` 并渲染 REPL。

**⚠️ 不要从第一行硬读。** 先抓主干：

```ts
export async function main() {
  profileCheckpoint('main_function_start')

  // SECURITY: Prevent Windows from executing commands from current directory
  // 安全：防止 Windows 从当前目录执行命令（防 PATH 劫持）
  process.env.NoDefaultCurrentDirectoryInExePath = '1'

  initializeWarningHandler()
  process.on('exit', () => { resetCursor() })
  process.on('SIGINT', () => { /* Ctrl+C 处理 */ })

  // …大量 feature('XXX') 分支处理 deep link / ssh / assistant 等
  // …最后调用 setup() 并进入 REPL 渲染
}
```

### 这段代码在教什么
- **一上来就设安全环境变量**：`NoDefaultCurrentDirectoryInExePath=1` 防止 Windows 从当前目录执行恶意程序（PATH 劫持）。这是"安全默认值"的典型做法。
- **信号处理**：`SIGINT`（Ctrl+C）和 `exit` 都要收尾（重置光标），否则终端会花屏。
- **`profileCheckpoint`**：性能打点，记录"启动到这一步花了多久"。

## 3.3 第三棒：[`src/setup.ts`](../source/src/setup.ts) 的 `setup()`

> 📁 本节源码：[`src/setup.ts`](../source/src/setup.ts)

`setup()` 负责"办入住"：校验 Node 版本、建立 messaging socket、处理 git worktree、抓取 hook 配置快照、预热插件、发 `tengu_started` 埋点。

```ts
export async function setup(cwd, permissionMode, allowDangerouslySkipPermissions, ...) {
  // Check for Node.js version < 18
  // 检查 Node 版本是否低于 18
  const nodeVersion = process.version.match(/^v(\d+)\./)?.[1]
  if (!nodeVersion || parseInt(nodeVersion) < 18) {
    console.error(chalk.bold.red(
      'Error: Claude Code requires Node.js version 18 or higher.'))
    process.exit(1)
  }
  // …设置 cwd → 抓 hook 快照 → 初始化文件变更监听
  // → 处理 worktree → 预热命令/插件 → 发埋点
}
```

### `setup()` 大致做了这些事（按顺序）
| 步骤 | 做什么 | 中文说明 |
|------|--------|----------|
| 1 | 校验 Node ≥ 18 | 版本不够直接退出 |
| 2 | 设置 `cwd` | 确定工作目录 |
| 3 | 抓 hook 配置快照 | 记录用户的 hook 设置（钩子脚本） |
| 4 | 初始化文件变更监听 | 监视项目文件变化 |
| 5 | 处理 git worktree | 可能切换到独立工作树 |
| 6 | 预热命令 / 插件 | 提前加载，减少首次使用卡顿 |
| 7 | 发 `tengu_started` 埋点 | 内部监控用，与学习无关，跳过即可 |

> **学习要点**：`setup()` 里的英文注释非常规范（每段都解释"为什么"）。初学者可以把它当**英语 + 架构双语教材**逐行读。
> 注意 `tengu_started` 这种"埋点事件名"——这是内部监控用的，和你的学习无关，直接跳过。

## 3.4 三棒交接图
```
cli.tsx  main()          ← 只做参数判断，重活全靠动态 import
   │
   ├─ --version ─────────→ 打印版本，return（零加载）
   ├─ bridge/daemon ─────→ 转给对应模式模块
   └─ 正常启动 ──────────→ main.tsx  main()
                              │
                              ├─ 设安全环境变量
                              ├─ 信号处理（SIGINT/exit）
                              ├─ feature 分支处理
                              └─ setup.ts  setup()
                                    │
                                    ├─ 验 Node ≥ 18
                                    ├─ cwd / hook / worktree
                                    ├─ 预热插件
                                    └─ 渲染 REPL → 进入对话循环
```

## 3.5 本篇小结
- **三棒接力**：`cli.tsx`（门卫看参数）→ `main()`（大堂总调度）→ `setup()`（办入住）。
- `cli.tsx` 的**动态 import + 快速路径**是性能优化范本。
- `main.tsx` 有 800KB，**先抓主干别硬读**。
- `setup.ts` 的英文注释质量最高，最适合当中英对照教材。
