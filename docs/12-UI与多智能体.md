## 12.1 UI 渲染：React + Ink 画在终端里
终端不是网页，没有 DOM。Claude Code 用的是 **Ink**——一个把 React 渲染到终端的框架。

| 目录 | 文件数 | 作用 |
|------|--------|------|
| `src/components/` | 389 | UI 组件（终端里显示的界面元素） |
| `src/ink/` | 96 | 底层渲染封装（Ink 框架的定制） |
| `src/hooks/` | 104 | 组件用的 React Hooks |
| `src/screens/` | 3 | 整屏界面 |
| `src/context/` | 9 | React Context 提供者 |
| `src/keybindings/` | 14 | 快捷键定义 |
| `src/vim/` | 5 | 终端里的 vim 键位编辑 |

### `src/ink/` 内部结构（96 文件）
Ink 不是装个依赖就完了——他们做了大量定制：

| 文件 / 目录 | 作用 |
|-------------|------|
| `ink.tsx` | 主实现 |
| `dom.ts` | 自己实现的一套"终端 DOM"（节点树） |
| `layout/` | 布局（配合 `native-ts/yoga-layout`） |
| `events/` | 键盘 / 输入事件 |
| `components/` | Ink 的基础组件（Box、Text 等） |
| `frame.ts` / `log-update.ts` | 帧管理、增量刷新（终端不能真的"重绘"，只能局部改） |
| `focus.ts` / `hit-test.ts` | 焦点管理、点击命中测试（终端里也能"点"） |
| `measure-text.ts` / `measure-element.ts` | 测量文字宽度（中文/emoji 宽度不同） |
| `colorize.ts` / `Ansi.tsx` | 颜色与 ANSI 转义 |
| `bidi.ts` | 双向文字（阿拉伯语等从右往左） |

> **`measure-text.ts` 解决的是个真实痛点**：终端里一个中文字符占 2 列、一个 emoji 可能占 2 列、组合 emoji 更复杂。算错宽度，边框就会歪。所以"测量文字宽度"是一个专门模块。

### Ink 是什么
**Ink = 用 React 写命令行界面**。你写的还是 React 组件：

```tsx
// 伪示例：Ink 组件的写法
<Box flexDirection="column">
  <Text color="green">✓ 文件已修改</Text>
  <Text dimColor>a.txt: 3 处替换</Text>
</Box>
```

Ink 把这些组件渲染成**终端的 ANSI 转义字符**（颜色、光标移动、清屏）。

### 为什么用 React 写终端
| 好处 | 说明 |
|------|------|
| 组件化 | 界面能拆成可复用组件 |
| 状态驱动 | 数据变了自动重渲染，不用手动清屏重画 |
| 生态复用 | React 的 hooks / context 全能用 |

> **学习建议**：UI 这块（389 个组件）是整个项目最庞大的部分，但**对理解架构帮助最小**。除非你想做终端 UI，否则可以先跳过，需要时再按需看。

## 12.2 本仓库特有的多智能体模块
这个仓库（`hangsman/claude-code-source`）比原版 Claude Code 多了一些模块，主要集中在多智能体和记忆：

| 目录 | 文件数 | 含义 |
|------|--------|------|
| `src/buddy/` | 6 | **伙伴 / 宠物系统**：13 种物种 × 5 档稀有度的虚拟宠物（详见 [15 篇](15-常量·技能与伙伴系统.md)） |
| `src/memdir/` | 8 | 记忆目录系统（`loadMemoryPrompt` 定义在 `memdir.ts:419`） |
| `src/coordinator/` | 1 | **协调器模式**：一个协调者调度多个 worker 智能体（深入代码见 [15 篇 15.5](15-常量·技能与伙伴系统.md)） |
| `src/commands/agents/` | 2 | 内置子智能体定义（`agents.tsx` + `index.ts`） |
| `src/skills/` | 20 | 技能系统（可插拔能力包，详见 [15 篇](15-常量·技能与伙伴系统.md)） |
| `src/utils/swarm/` | — | "蜂群"：多智能体协作的底层工具 |

### 协调器（`src/coordinator/`）
这是多智能体编排的核心，但只有 1 个文件——因为它本质上是**在 `AgentTool` 之上的一层封装**：

```
协调器（coordinator）
   ├─ 拆解任务
   ├─ 派给 worker 1（子 Agent）
   ├─ 派给 worker 2（子 Agent）
   ├─ 收集结果
   └─ 汇总 / 验收
```

回忆 [10 篇](10-子智能体与计划模式.md)：子智能体就是递归调 `query()`。协调器只是**管理多个子智能体**的调度与结果汇总。

> 注意 `feature('COORDINATOR_MODE')`——这个模式在构建期可能被关掉。如果在你的版本里搜不到实现，说明它没被打进包。

### 技能系统（`src/skills/`）
**Skill（技能）= 可插拔的能力包**。它和"工具"的区别：

| 概念 | 是什么 | 例子 |
|------|--------|------|
| Tool（工具） | 一个具体的**动作** | 读文件、跑命令 |
| Skill（技能） | 一套**领域知识 + 工作流** | "如何写 PPT"、"如何做代码审查" |

技能通常是一个目录，里面有 `SKILL.md`（说明何时用、怎么用）+ 辅助脚本。模型通过 `Skill` 工具加载技能，把技能内容读进上下文，然后按里面的指引干活。

### 记忆目录（`src/memdir/`）
`loadMemoryPrompt()` 从这里读记忆，然后塞进系统提示词（见 [05 篇](05-提示词与命令.md)的 `systemPromptSection('memory', ...)`）。

> 记忆的完整机制（索引 + 分文件 + 自动整理）见 [07 篇 7.6 节](07-服务层详解.md)。

## 12.3 如果你想做"多智能体"，从哪下手

> 📁 本节源码：[`src/commands/agents/agents.tsx`](../source/src/commands/agents/agents.tsx)

按难度递增：

| 目标 | 看哪里 | 难度 |
|------|--------|------|
| 单个 Agent 循环调工具 | `query.ts` 的 `while(true)`（06 篇） | ⭐ |
| Agent 派子 Agent | `tools/AgentTool/runAgent.ts`（10 篇） | ⭐⭐ |
| 一个协调者管多个 worker | `src/coordinator/` + `TeamCreateTool` | ⭐⭐⭐ |
| 带角色分工的团队 | [`src/commands/agents/agents.tsx`](../source/src/commands/agents/agents.tsx) + `src/skills/` | ⭐⭐⭐⭐ |

> **最务实的路径**：先把 06 篇的 `while(true)` 手写一遍（几十行就能跑），你会瞬间理解所有 Agent 框架。再往上加"子 Agent"就是加一个工具而已。
