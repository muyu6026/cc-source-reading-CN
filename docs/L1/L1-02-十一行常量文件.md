## 1. 精读正文

全文件 11 行，逐字摘录（中间空行保留）：

```ts
1  │ // In its own file to avoid circular dependencies
2  │ export const FILE_EDIT_TOOL_NAME = 'Edit'
3  │
4  │ // Permission pattern for granting session-level access to the project's .claude/ folder
5  │ export const CLAUDE_FOLDER_PERMISSION_PATTERN = '/.claude/**'
6  │
7  │ // Permission pattern for granting session-level access to the global ~/.claude/ folder
8  │ export const GLOBAL_CLAUDE_FOLDER_PERMISSION_PATTERN = '~/.claude/**'
9  │
10 │ export const FILE_UNEXPECTEDLY_MODIFIED_ERROR =
11 │   'File has been unexpectedly modified. Read it again before attempting to write it.'
```

### 1.1 第 1–2 行：存在理由 + 第一个常量

```ts
1  │ // In its own file to avoid circular dependencies
2  │ export const FILE_EDIT_TOOL_NAME = 'Edit'
```

第 1 行和 L1-01 的 `toolName.ts` 是同一句话的变体：「单独成文件，为了避免循环依赖」。`Edit` 工具的名字被权限层、hook 层、UI 层共同需要，谁都不能当它的「房东」，于是它住在叶子常量文件里。

第 2 行的结构上一课逐词拆过：`export`（交出去）+ `const`（不能再赋值）+ 名字 + 字符串值。**中文念法**：「导出常量 `FILE_EDIT_TOOL_NAME`，值是 `'Edit'`。」

### 1.2 第 4–5、7–8 行：两个「匹配模式」

```ts
4  │ // Permission pattern for granting session-level access to the project's .claude/ folder
5  │ export const CLAUDE_FOLDER_PERMISSION_PATTERN = '/.claude/**'
```

**中文念法（第 4 行）**：「权限模式——用于授予对项目内 `.claude/` 文件夹的会话级访问。」

第 5 行的值 `'/.claude/**'` 是本课第一个新知识点。**它只是一个普通字符串**——单引号里有什么，值就是什么。但这个字符串的内容是一种「匹配模式」（glob 模式），会被权限系统拿去和文件路径做比对：

- `*` 在 glob 模式里表示「任意一串字符」（但不跨 `/`）；
- `**` 表示「**任意多层路径**」，包括零层。`/.claude/**` 就是「`.claude/` 目录以及它下面任意深度的任何文件」；
- 所以这条模式命中 `/.claude/settings.json`、`/.claude/a/b/c.md` 等一切位于 `.claude/` 里的路径。

**要点：`**` 是字符串内容表达「匹配语义」，不是 TypeScript 语法。** 编译器对 `**` 没有任何特殊处理；它是权限系统拿到这个字符串之后自己解释的。第 8 行的 `'~/.claude/**'` 同理，`~` 开头表示用户主目录下的全局 `.claude/`——`~` 同样只是字符串内容，由消费方解释。

### 1.3 第 10–11 行：等号后换行

```ts
10 │ export const FILE_UNEXPECTEDLY_MODIFIED_ERROR =
11 │   'File has been unexpectedly modified. Read it again before attempting to write it.'
```

这是本课第二个新知识点：**为什么等号后面换行，而不是把整句写在一行？**

- 语法上完全允许写一行——字符串字面量不能直接跨行，但「等号后换行」不是跨行字符串，而是**把赋值表达式拆成两行**：第 10 行是「赋值给谁」，第 11 行是「赋什么值」。
- 不直接写一行的原因是**格式约定**：这行字符串超过 80 字符，本仓库由格式化工具（Prettier 一类）统一控制行宽，超长的赋值就自动折成「等号结尾 + 下一行缩进的值」。
- 注意第 11 行开头那两个空格是**缩进**，不是字符串的一部分；字符串内容从 `'` 开始、到 `'` 结束，一行都没断。

**中文念法**：

> 「导出常量 `FILE_UNEXPECTEDLY_MODIFIED_ERROR`，它的值是（下一行）那句报错文案。」

和它对照的是第 5、8 行——那两个字符串不长，就写在同一行。**换不换行不改变语义，只取决于一行放不放得下。**

## 2. 核心问题（路线卡片原题的完整解答）

### 2.1 第 10–11 行 `=` 后面换行，为什么不用引号包成一行？

三个层面回答：

1. **「包成一行」本来就没问题**——单引号字符串不能直接跨行书写，但这里是「一行放不下整个赋值」，语法允许把值放到等号的下一行，逗号、运算符、等号结尾都可以换行。
2. **不写一行的真实原因是行宽纪律**。第 11 行有 85 个字符，放同一行会突破仓库统一格式化后的行宽上限。格式化工具宁可折行也不留超长行。
3. **千万不要写两个引号拼接**——比如第 10 行 `'...modified.'` + 第 11 行 `'Read it again...'`。那就变成两个字符串，需要 `+` 连接，平白多了运行时拼接。现在这种写法字符串在源码里仍是**一个完整的字面量**，只是书写位置换了行。

### 2.2 `'/.claude/**'` 里的 `**` 是什么语法？

**不是 TypeScript 语法。** 它是字符串**内容**，一种叫 glob 的路径匹配模式的写法：`**` 代表「任意多层目录」。权限系统把用户访问的路径和这个模式比对，命中就表示「访问的是项目 `.claude/` 目录里的东西」，从而决定是否放行。

判别口诀：**看到 `**` 先看它在引号里还是引号外**。在引号里（本课）它是给「模式匹配器」看的数据；在引号外 TypeScript 里 `**` 另有一个含义（乘方运算符，本仓库几乎不用）。

### 2.3 「常量文件」在项目里的作用是什么？

一句话：**集中改一处，全项目生效**。展开说三层：

1. **改文案只动一个地方**。`FILE_UNEXPECTEDLY_MODIFIED_ERROR` 这句报错如果散落在各处手写，改一个字要找遍全仓；集中成常量后，改第 11 行一处，所有使用者同步生效。
2. **语义有名字**。代码里出现 `FILE_UNEXPECTEDLY_MODIFIED_ERROR`，读者立刻知道「这是那个『文件被意外修改』的错误」；出现一长串英文字符串，则要逐字读。
3. **断开循环依赖**（L1-01 的主题）。共享者越多，越要住在没人反向依赖的叶子上——本文件的 4 个常量正是如此。

### 2.4 谁 import 它？

实测 `grep -rln "FileEditTool/constants" source/src` 命中 **30 个文件**，横跨好几层：

- 工具层：`FileEditTool/FileEditTool.ts`、`FileWriteTool/FileWriteTool.ts`（**两个工具共享同一句报错文案**——这正是「集中改一处」的实例：触发条件必须一致，所以共用一份常量而不是各写一份）；
- 常量层：`constants/prompts.ts`、`constants/tools.ts`；甚至别的工具的常量文件也来取名字——`REPLTool/constants.ts` 第 4 行 `import { FILE_EDIT_TOOL_NAME } from '../FileEditTool/constants.js'`（实测）；
- 服务层与工具函数层：`services/compact/`、`utils/permissions/filesystem.ts`、`utils/sandbox/sandbox-adapter.ts` 等十几个文件。

一个 11 行文件，4 个常量，被 30 个文件引用——常量文件是整个仓库的「公共词汇表」。

## 3. 常见误读

**误读 1：以为 `**` 是 TypeScript 或正则的语法。**
它在这里只是引号内的普通字符，消费它的权限匹配器才赋予它「任意多层路径」的含义。同理，第 8 行的 `~` 也不是什么 TS 运算符，就是字符串第一个字符。

**误读 2：以为第 10–11 行是「一行放不下的字符串用 `+` 拼起来」。**
没有 `+`，也没有两个字符串。等号后换行只是把**一个赋值语句**写成两行，值仍是一个完整字符串字面量。写成 `+` 拼接反而多余。

**误读 3：以为常量文件里放什么都行，比如放个函数。**
叶子常量文件的价值恰恰在「只导出字面量、不 import 任何东西」——一旦往里加函数、加 import，它就有了自己的依赖，引用它的 30 个文件就多了一条潜在的环。**保持叶子纯净，是这类文件能当「公共词汇表」的前提。**

## 5. 合书自测

**1. 等号后换行的写法，字符串还是一个吗？**

<details>
<summary>参考答案</summary>

是一个。换行只是把赋值语句排成两行，第 11 行的值仍是一个完整字符串字面量，中间没有 `+`、没有两个引号。

</details>

**2. `'/.claude/**'` 里的 `**` 是 TS 语法吗？它由谁解释？**

<details>
<summary>参考答案</summary>

不是。它是字符串内容里的 glob 匹配模式，表示「任意多层路径」；由消费这个字符串的权限匹配逻辑解释，编译器对它不做任何特殊处理。

</details>

**3. 不看文件，说出这个文件里 4 个常量的名字。**

<details>
<summary>参考答案</summary>

`FILE_EDIT_TOOL_NAME`（'Edit'）、`CLAUDE_FOLDER_PERMISSION_PATTERN`（'/.claude/**'）、`GLOBAL_CLAUDE_FOLDER_PERMISSION_PATTERN`（'~/.claude/**'）、`FILE_UNEXPECTEDLY_MODIFIED_ERROR`（那句报错文案）。

</details>

**4. 为什么报错文案要两个工具共用一份常量，而不是各写一份？**

<details>
<summary>参考答案</summary>

两个工具触发「读完之后文件又被改过」的条件必须一致，共用一份保证文案永远同步；同时上层按字符串分类重试逻辑时只需匹配一次。

</details>

**5. 如果往这个常量文件里加一个 `import`，会破坏什么？**

<details>
<summary>参考答案</summary>

它不再是「不依赖任何人的叶子」，30 个引用者都可能经由这条新依赖与别的模块成环；解耦价值随之消失。

</details>
