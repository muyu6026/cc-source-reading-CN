## 1. 先分清两个世界：类型与值

这个文件里有两个名字长得像兄弟，但活在不同世界：

| 名字 | 是什么 | 编译后还在吗 | 能打印吗 |
| --- | --- | --- | --- |
| `CommandSemantic` | **类型**：描述「一种函数长什么样」 | ❌ 消失 | ❌ 不能 |
| `DEFAULT_SEMANTIC` | **值**：一个真实的函数 | ✅ 还在 | ✅ 能 |

**念法区分**：看到首字母大写的驼峰 + `type` 关键字，是类型；看到 `const` / `function` 开头，是值。这节课的难点全在「同一个东西既是类型又是值」这件事上——比如函数，它**作为值**可以传递，**作为类型**可以被描述。

## 2. 精读正文（逐行，行号为批注版行号）

### 2.1 第 11–19 行：给一种「函数长相」起名字

```ts
export type CommandSemantic = (
// CommandSemantic 签名：(exitCode, stdout, stderr) → { isError, message? }。stdout/stderr 参数大部分语义函数没收（下划线前缀），留给将来需要输出内容的判断。
  exitCode: number,
  stdout: string,
  stderr: string,
) => {
  isError: boolean
  message?: string
}
```

**逐段念**：

| 片段 | 念法 |
| --- | --- |
| `export type CommandSemantic =` | 「发明一个类型，叫 `CommandSemantic`」 |
| `(` … `)` | 参数列表：三个参数，各带类型标签 |
| `) =>` | 「这个类型描述的是**函数**；箭头右边是它的返回值」 |
| `{ isError: boolean }` | 返回值是一个对象，必须有 `isError` 字段（布尔） |
| `message?: string` | 这个字段**可以没有**，有就得是字符串 |

**整句念法**：
> 「`CommandSemantic` 是一种函数：收三个参数（数字、字符串、字符串），返回一个对象，对象里有必填的 `isError`（布尔）和可选的 `message`（字符串）。」

三个细节：

1. **箭头 `=>` 在这里不是箭头函数**。它在 `type` 语句里，表示「函数类型」的返回位置。整行没有任何代码被执行——这只是一个形状描述。
2. **`stdout` / `stderr` 是位置参数名**，但在这类类型里名字只是给人看的。真正重要的是**顺序和类型**：第 2 个是字符串，第 3 个是字符串。TypeScript 检查的是位置，不是名字。
3. **返回对象里的字段没有逗号**。对象**类型**里用换行分隔即可；但对象**值**里必须用逗号。这是两种「花括号」的区别。

### 2.2 第 21–29 行：一个值，被类型检查

```ts
/**
 * Default semantic: treat only 0 as success, everything else as error
 */
// DEFAULT_SEMANTIC：只有 0 算成功。
const DEFAULT_SEMANTIC: CommandSemantic = (exitCode, _stdout, _stderr) => ({
  isError: exitCode !== 0,
  message:
    exitCode !== 0 ? `Command failed with exit code ${exitCode}` : undefined,
})
```

注释说得很直白：**退出码 0 = 成功，其余都算错误**——这是 Unix 的通用约定，也是所有没被特别关照的命令的兜底规则。**第 25 行有三个知识点挤在一起**：

**① `: CommandSemantic` 是类型标注**（讲义 [§2.4](../00a-TypeScript地基.md)）。它声明「右边这个值必须符合那种函数形状」。写错参数类型、漏掉 `isError`，编译期就报错。

**② `(exitCode, _stdout, _stderr)` 的下划线**：前导 `_` 是约定，表示「这个参数我收下了，但不打算用」。这里只有退出码参与判断，输出内容用不上。TypeScript 允许少写尾部参数，但作者把三个都写出来，是为了让「形状」一眼可见。

**③ `=> ({` 的圆括号**——这是 0 基础最容易栽的一跤。

```ts
const f = (x) => ({ value: x })   // ✅ 返回对象 {value: x}
const g = (x) => { value: x }     // ❌ 返回 undefined
```

原因：箭头右边紧跟 `{` 时，JavaScript 把它当成**函数体**的开始（一个代码块），而不是对象。套一层圆括号，等于告诉解析器「这里是一个表达式，先算它」。

**第 26 行** `isError: exitCode !== 0` 是对象的一个键值对：键是 `isError`，值是「退出码不等于 0」这个布尔表达式。

**第 27–28 行**是三元表达式：

```ts
exitCode !== 0 ? `Command failed with exit code ${exitCode}` : undefined
```

**念法**：「退出码不为 0，就给一句带退出码的错误消息；否则给 `undefined`。」

注意这里**显式写了 `message: undefined`**，而不是省掉这个字段。因为类型里 `message?` 是可选，两种写法都合法；显式写出来，让「成功时没有消息」这件事在代码里看得见。

### 2.3 第 34–44 行：把函数塞进字典

```ts
const COMMAND_SEMANTICS: Map<string, CommandSemantic> = new Map([
// COMMAND_SEMANTICS 按基名查。注意没有管道感知——管道命令的退出码取哪段由调用方决定（见下面启发式提取）。
  // grep: 0=matches found, 1=no matches, 2+=error
// grep/rg：0=有匹配，1=无匹配（给人类消息 No matches found），2+=真错误。
  [
    'grep',
    (exitCode, _stdout, _stderr) => ({
      isError: exitCode >= 2,
      message: exitCode === 1 ? 'No matches found' : undefined,
    }),
  ],
```

**第 34 行**：`Map<string, CommandSemantic>` 读作「一张表，键是字符串，值是 `CommandSemantic` 类型的函数」（讲义 [§2.7](../00a-TypeScript地基.md)）。

**这段真正的新东西**：数组的第二个元素是一个**箭头函数**，它被当作**普通值**放进 `Map`。没有 `function` 关键字，没有名字，就是一个「匿名函数值」。

为什么能做到：**函数在 JavaScript 里是一等公民**——能赋值给变量、能当参数、能当返回值、能放进数组和字典。这个仓库大量利用这一点，把「按命令名选一段逻辑」写成查表，而不是写一长串 `if/else`。

**`grep` 的语义**也值得记：`exitCode >= 2` 才算错误，`1` 只表示「没匹配」——`grep` 没找到东西不是故障。这就是本节开头 `DEFAULT_SEMANTIC` 不够用的原因：**不同命令的退出码含义不同**。

### 2.4 第 103–108 行：取出函数、再返回函数

```ts
function getCommandSemantic(command: string): CommandSemantic {
  // Extract the base command (first word, handling pipes)
  const baseCommand = heuristicallyExtractBaseCommand(command)
  const semantic = COMMAND_SEMANTICS.get(baseCommand)
  return semantic !== undefined ? semantic : DEFAULT_SEMANTIC
}
```

**第 103 行**：返回类型写的是 `CommandSemantic`——**这个函数返回的是另一个函数**。这是「函数也是值」最直接的证据：函数可以当返回值。

**第 106 行**：`Map.get` 的返回类型是 `CommandSemantic | undefined`（查不到就是 `undefined`）。这就是 L0-06 那个联合类型在实际代码里的样子。

**第 107 行**：用三元表达式兜底——查到了就用查到的，查不到用默认的。**念法**：「表里有就用表里的，没有就用默认语义。」

### 2.5 第 145–146 行：把取出来的函数调用掉

```ts
  const semantic = getCommandSemantic(command)
  const result = semantic(exitCode, stdout, stderr)
```

第 145 行拿到的是一个**函数值**，存进变量 `semantic`；第 146 行才真正**调用**它——注意名字后面有圆括号和三个实参。**「取函数」和「调函数」是两个时刻**：`getCommandSemantic` 只负责选，执行发生在调用方。

> 同一套写法在 [`source/src/tools/PowerShellTool/commandSemantics.ts`](../../source/src/tools/PowerShellTool/commandSemantics.ts) 第 140 行换成了 `?? DEFAULT_SEMANTIC` 兜底，可以和这里的三元表达式对照着看。

## 3. 三个问题（路线图 L0-7 卡片）

### 问题 1：返回值里的 `message?: string` 是什么写法？

是**可选属性**（讲义 [§2.3](../00a-TypeScript地基.md) 表格第二行）。`?` 跟在**属性名**后面，含义是「这个字段可能存在，也可能不存在」。三件事要说清：

1. **它的类型是 `string | undefined`**，不是 `string | null`，也不是「任意类型」。
2. **它只出现在类型里**。写值的时候不能写 `message?: '...'`——`?` 是类型语法，不是值的语法。
3. **读的人必须处理「没有」的情况**。谁拿到一个 `CommandSemantic` 的返回值，访问 `result.message` 得到的类型就是 `string | undefined`，直接当字符串用会编译报错，得先判断或兜底。

### 问题 2：第 22–26 行的 `DEFAULT_SEMANTIC` 和这个类型是什么关系？

**类型是模具，值是成品**：`CommandSemantic`（第 11 行）描述「一个合格的语义函数必须长什么样」；`DEFAULT_SEMANTIC`（第 25 行）是**一个具体的函数**，被 `: CommandSemantic` 要求符合那个形状。

关系可以这样验：把第 26 行改成 `isError: 'yes'`，编译器立刻报错——因为模具要求布尔，成品给了字符串。**没有这行标注，函数照样能跑，但错误要等运行时才现形。**

它在系统里的角色是**兜底**：`COMMAND_SEMANTICS` 表里只登记了 6 个命令（`grep`、`rg`、`find`、`diff`、`test`、`[`），其余所有命令都走 `DEFAULT_SEMANTIC`（第 107 行）。

### 问题 3：`(exitCode, _stdout, _stderr) => ({...})` 为什么返回值要套一层圆括号？

因为**不套就会改变语法含义**：

```ts
(x) => { a: 1 }     // 解析成：函数体里有个标签 a 和表达式 1，返回 undefined
(x) => ({ a: 1 })   // 解析成：返回对象 { a: 1 }
```

箭头函数有两条规则：右边是**表达式**就隐式返回它的值；右边是**代码块**就必须显式 `return`。而 `{` 天然被优先理解成代码块。

**记忆口诀**：**返回对象，套层括号；要么就写 `return`**（`(x) => { return { value: x } }` 也合法，只是啰嗦）。

## 4. 常见误读

| ❌ 0 基础最可能这样读 | ✅ 实际是什么 |
| --- | --- |
| `CommandSemantic` 是个对象/常量，运行时能拿到 | 它是**类型**，编译后消失；运行时存在的是 `DEFAULT_SEMANTIC` 这个函数值 |
| `=> ({ ... })` 的圆括号只是排版习惯 | 缺了它，`{}` 被当成函数体，函数返回 `undefined` |
| `message?: string` 表示「可以是字符串或 null」 | 表示「可以没有这个字段」，类型是 `string \| undefined` |

## 6. 合书自测

1. `CommandSemantic` 是类型还是值？`DEFAULT_SEMANTIC` 呢？各举一条证据。
2. 用一句中文念出第 11–19 行。
3. `message?: string` 的类型到底是什么？为什么调用方不能直接 `result.message.length`？
4. `=> ({ ... })` 里的圆括号去掉会发生什么？为什么？
5. `Map<string, CommandSemantic>` 这个类型里，`string` 和 `CommandSemantic` 各指什么？
6. 表里查不到命令时，走哪条路？这条路的规则是什么？

<details>
<summary>参考答案（先自己写，再展开）</summary>

1. `CommandSemantic` 是**类型**（`export type` 开头，编译后消失）；`DEFAULT_SEMANTIC` 是**值**（`const` 定义的真实函数，能被 `Map` 兜底、能被调用）。
2. 「`CommandSemantic` 是一种函数：收三个参数（数字、字符串、字符串），返回一个对象，里面有必填的 `isError`（布尔）和可选的 `message`（字符串）。」
3. 类型是 `string | undefined`。因为字段可能不存在，直接读 `.length` 可能对 `undefined` 取属性，编译期就会报「对象可能为 undefined」。
4. `{}` 会被解析成函数体，函数没有 `return`，返回 `undefined`。要返回对象就必须套圆括号（或写显式 `return`）。
5. `string` 是键的类型（命令基名，如 `grep`）；`CommandSemantic` 是值的类型（处理该命令的函数）。
6. 走 `DEFAULT_SEMANTIC`（第 107 行的三元兜底，或 PowerShell 版的 `??`）。规则是「只有退出码 0 算成功，其余都算错误」，并给出 `Command failed with exit code N`。

</details>
