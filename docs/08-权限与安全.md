# 08 · 权限与安全系统

> 本篇目标：看懂 Claude Code 的"招牌安全机制"——AI 想动手之前，怎么判断"允许 / 问用户 / 拒绝"。
> 对应源码：`src/utils/permissions/`（24 个文件）

---

## 8.1 为什么这块最该读
`src/utils/permissions/` 有 **24 个文件**，是除 `utils/` 外逻辑最密集的区域之一。它回答一个根本问题：

> **一个能执行任意命令的 AI，凭什么让人放心用？**

答案是三层设计：**默认最小信任 + 规则可配置 + 危险操作必问**。这套思路直接能用在你自己的 AI 工具上。

---

## 8.2 六种权限模式（PermissionMode）

> 📁 本节源码：[`src/utils/permissions/PermissionMode.ts:43-75`](../source/src/utils/permissions/PermissionMode.ts#L43-L75)

模式决定了"默认情况下要不要问你"。

| 英文模式 | 中文 | 行为 |
|----------|------|------|
| `default` | 默认 | 危险操作弹窗问你 |
| `plan` | 计划模式 | 只允许"规划"，不允许改文件 / 跑命令 |
| `acceptEdits` | 自动接受编辑 | 文件编辑直接过，命令仍可能问 |
| `bypassPermissions` | 跳过权限 | 全部放行（危险，对应 `--dangerously-skip-permissions`） |
| `dontAsk` | 不问 | 把所有"问"直接转成"拒绝" |
| `auto`（内部） | 自动模式 | 用 AI 分类器代替弹窗决定 |

```ts
// src/utils/permissions/PermissionMode.ts:43-75（配置表原文节选，中文注释为后加）
const PERMISSION_MODE_CONFIG = {
  default:           { title: 'Default',  symbol: '',   color: 'text' },   // 默认
  plan:              { title: 'Plan Mode', symbol: PAUSE_ICON, color: 'planMode' }, // 计划模式
  acceptEdits:       { title: 'Accept edits', ... },   // 自动接受编辑
  bypassPermissions: { title: 'Bypass Permissions', ... }, // 跳过权限（红色警告）
  dontAsk:           { title: "Don't Ask", ... },      // 不问（直接拒绝）
  // auto: 内部模式，用 AI 分类器代替用户点击
}
```

> 注意 `bypassPermissions` 配上**红色警告**——UI 层面就在提醒"你现在很危险"。

## 8.3 核心判定函数：`hasPermissionsToUseTool()`

> 📁 本节源码：[`src/utils/permissions/permissions.ts:473-956`](../source/src/utils/permissions/permissions.ts#L473-L956)

这是每次工具调用前的"守门员"。

```ts
// src/utils/permissions/permissions.ts:473-956（结构简化示意，真实函数 484 行）
export const hasPermissionsToUseTool = async (tool, input, context, ...) => {
  const result = await hasPermissionsToUseToolInner(tool, input, context)

  // 如果结果是 allow：在 auto 模式下重置"连续拒绝"计数
  if (result.behavior === 'allow') { /* ... */ return result }

  // 如果结果是 ask（要问用户）：
  if (result.behavior === 'ask') {
    // dontAsk 模式：把"问"直接变成"拒绝"，且放在最后做，防止被提前 return 绕过
    if (context.mode === 'dontAsk') {
      return { behavior: 'deny', decisionReason: { type: 'mode', mode: 'dontAsk' } }
    }
    // auto 模式：不弹窗，改用 AI 分类器判断（feature('TRANSCRIPT_CLASSIFIER')）
    if (feature('TRANSCRIPT_CLASSIFIER') && context.mode === 'auto') {
      // 涉及安全校验（如敏感文件路径）且分类器无权批准的，保持 ask/deny
    }
  }
  // …deny 分支原样返回
}
```

### 三态返回值
| 结果 | 含义 | 后续动作 |
|------|------|----------|
| `allow` | 允许 | 直接执行 |
| `ask` | 需要问 | 弹窗让用户点"同意 / 拒绝" |
| `deny` | 拒绝 | 不执行，把拒绝原因告诉模型 |

### 两个精妙细节
**① `dontAsk` 的判断放在"最后"**

注释里写得很清楚：`dontAsk` 的转换**必须放在最后做**，否则会被前面某些分支的 `return` 提前绕过。这是"**顺序即安全**"的典型——安全兜底一定要放在所有可能提前返回的路径之后。

**② `auto` 模式不是"全放行"**

`auto` 模式用 AI 分类器代替弹窗，但**涉及安全校验（如敏感文件路径）时，分类器无权批准**，仍保持 `ask` / `deny`。这叫"**分类器不能给自己授权**"——防止 AI 自己放行自己。

## 8.4 配套文件（知道名字即可，按需深读）
| 文件 | 作用 |
|------|------|
| `dangerousPatterns.ts` | 识别"危险命令模式"（如 `rm -rf`、改系统文件） |
| `bashClassifier.ts` / `yoloClassifier.ts` | 判断某条 bash 命令该不该放行 |
| `filesystem.ts` | 文件读写权限判定 |
| `pathValidation.ts` | 路径合法性校验（防 `../` 越权） |
| `permissionRuleParser.ts` | 解析你写在 `settings.json` 里的 allow / deny 规则 |
| `PermissionMode.ts` | 六种模式的定义与配置 |
| `PermissionResult.ts` | 判定结果的结构 |

### 重点说说 `pathValidation.ts`

> 📁 本节源码：[`src/utils/permissions/pathValidation.ts`](../source/src/utils/permissions/pathValidation.ts)

它防的是"**路径穿越**"攻击：

```
用户/模型传入: ../../../../etc/passwd
               ↓
必须校验：解析后的真实路径是否还在允许的根目录内
               ↓
不在 → 拒绝
```

> 这是所有"能读文件"的应用都必须做的检查。只做字符串前缀判断（`startsWith('/home')`）是不够的，因为 `..` 和软链接都能绕过，必须**解析成绝对真实路径**再判断。

## 8.5 权限判定的完整时机
权限判定在工具执行流水线里的位置（详见 [04 篇](04-工具系统.md)）：

```
模型返回 tool_use
      ↓
executePreToolHooks()        ← 钩子可以先拦一道
      ↓
hasPermissionsToUseTool()    ← 权限判定（本篇）
      ↓
  ┌───┴────┬────────┐
  ▼        ▼        ▼
allow    ask      deny
  │        │        │
  │      弹窗       │
  │        │        │
  ▼        ▼        ▼
执行    执行/不执行  不执行，告诉模型原因
```

## 8.6 安全设计的通用原则（可以直接抄）
| 原则 | Claude Code 的做法 | 你能怎么用 |
|------|--------------------|------------|
| **默认最小信任** | 默认模式下危险操作必问 | 新工具默认 `ask`，别默认 `allow` |
| **安全兜底放最后** | `dontAsk` 转换放在所有 return 之后 | 所有"最终拦截"逻辑放函数末尾 |
| **分类器不能自授权** | `auto` 模式下敏感路径仍保持 ask/deny | AI 判定不能覆盖硬规则 |
| **路径解析后再判断** | `pathValidation.ts` 解析真实路径 | 别用字符串前缀判断路径安全 |
| **规则可配置** | `settings.json` 里写 allow/deny | 给用户逃生舱口 |
| **危险名字要刺眼** | `DANGEROUS_`、红色 UI | 让危险在代码和界面上都显眼 |

---

## 8.7 本篇小结
- 六种模式：`default / plan / acceptEdits / bypassPermissions / dontAsk / auto`。
- 守门员 `hasPermissionsToUseTool()` 返回 `allow / ask / deny` 三态。
- `dontAsk` 把"问"转"拒"，且**放在最后**防止被绕过。
- `auto` 模式用分类器代替弹窗，但**分类器无权批准敏感操作**。
- `pathValidation.ts` 防路径穿越，必须解析真实路径再判断。
