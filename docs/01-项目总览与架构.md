# 01 · 项目总览与架构

> 本篇目标：用最快的方式建立**全局地图**——它是什么、用什么技术、程序怎么流动。
> 对应源码：`package.json`、[`src/entrypoints/cli.tsx`](../source/src/entrypoints/cli.tsx)、[`src/main.tsx`](../source/src/main.tsx)、[`src/setup.ts`](../source/src/setup.ts)

---

## 1.1 这个项目是什么
`Claude Code` 是 Anthropic 出品的**终端里运行的 AI 编程智能体**（agentic coding tool）。

核心能力：
- 理解你的代码库
- 用自然语言帮你改文件
- 跑终端命令
- 处理整个开发工作流

**"agentic（智能体化）"的含义**：它不是一问一答，而是能**自主多步行动**——自己决定调哪个工具、看结果、再决定下一步，直到把任务做完。

## 1.3 ⚠️ 两个必须先懂的坑
### 坑 1：这是打包版，不能直接跑
`package.json` 的 `dependencies` 是**空的**（`{}`）。运行依赖在构建时被 Bun 内联进去了，所以 `npm install` 之后并不能直接运行。

**正确心态**：把它当"源码阅读对象"，**不要试图直接运行**。

### 坑 2：`feature('XXX')` 是构建期开关
源码里到处是：

```ts
if (feature('SOME_FLAG')) {
  // 这段代码只有开关打开时才会被打进最终包
}
```

这是 Bun 的**死代码消除（dead code elimination）**——没开的开关，整段代码在打包时被删掉。

所以：
- 你看到的 `feature('KAIROS')`、`feature('COORDINATOR_MODE')` 分支，在公开发布版里**可能根本不存在**；
- 读代码时看到不熟悉的功能，先怀疑"这是不是内部版才有的"；
- 别试图去"跑通"这些分支——它们在你的版本里可能连实现都没有。

## 1.4 整体架构与数据流
```
┌─────────────────────────────────────────────────────────────┐
│  你在终端输入 claude                                          │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
        src/entrypoints/cli.tsx  ◀── 二进制入口（cli.js）
        （快速路径：--version 零加载；--dump-system-prompt 等）
                            ▼
        src/main.tsx  →  main()   ◀── 主函数（808KB 大文件 = REPL 主体）
                            ▼
        src/setup.ts  →  setup()  ◀── 初始化（Node版本/工作区/Hook/插件/埋点）
                            ▼
        ┌──────────────────────────────────────────┐
        │  渲染 REPL（React + Ink 终端界面）          │
        │  src/components/ + src/ink/                │
        └───────────────────┬──────────────────────┘
                            ▼  用户输入 / 多轮对话
        src/QueryEngine.ts / src/query.ts  ◀── 查询引擎（对话主循环）
                            ▼
        src/services/api/claude.ts  ◀── 真正调用 Claude API（流式）
                            ▼
        模型返回 → 可能带 tool_use（工具调用）
                            ▼
        src/tools.ts  →  分发到具体工具（Bash/Read/Edit/Agent...）
                            ▼
        工具执行结果回灌给模型 → 继续下一轮，直到回答完成
```

### 用大白话再讲一遍
| 角色 | 文件 | 类比 |
|------|------|------|
| 开门 | `entrypoints/cli.tsx` | 大楼门卫，先看你要不要办正事（`--version` 直接打发） |
| 大堂 | `main.tsx` 的 `main()` | 大厅总台，处理各种分支、引导你去哪 |
| 办入住 | `setup.ts` 的 `setup()` | 入住登记：验身份、发房卡、登记信息 |
| 前台对话 | `QueryEngine.ts` / `query.ts` | 你和服务员的一问一答循环 |
| 打电话给大脑 | `services/api/claude.ts` | 打给 Claude 总部请示 |
| 双手 | `tools.ts` + `src/tools/` | 让 AI 真正动手干活 |

## 1.5 一次完整交互发生了什么（时序）
以你对 Claude 说"帮我把 a.txt 里的 foo 改成 bar"为例：

1. **入口** `cli.tsx` 判断不是 `--version` 这类快速路径，转给 `main()`。
2. **主函数** `main()` 解析参数、处理配置，调 `setup()` 做初始化。
3. **初始化** `setup()` 校验 Node ≥ 18、建 messaging socket、抓 hook 配置、预热插件、发 `tengu_started` 埋点。
4. **渲染** REPL 起来，等你输入。
5. **你回车** → 消息进入 `query()`。
6. **主循环** `while(true)` 第 1 轮：把消息 + 系统提示词 + 工具清单发给 `services/api/claude.ts`。
7. **模型返回** `tool_use: Read(a.txt)`。
8. **权限判定** `hasPermissionsToUseTool()` 判断读文件是否安全 → 返回 `allow`。
9. **执行工具** 走 `services/tools/` 的流水线，真的读文件。
10. **结果回灌** 把文件内容作为 `tool_result` 塞回消息列表。
11. **第 2 轮循环** 模型看到内容，返回 `tool_use: Edit(a.txt, foo→bar)`。
12. **权限判定** 改文件可能需要 `ask` → 弹窗问你 → 你同意。
13. **执行** 改完文件，返回结果。
14. **第 3 轮** 模型判断任务完成，返回纯文本"已改好"。
15. **跳出循环**，把最终回答渲染到终端。

> 这 15 步里，第 6~14 步就是"AI 智能体"的全部秘密。第 06 篇会把第 6 步的循环本体育给你看。

## 1.6 本篇小结
- 它是**终端里的 AI 编程智能体**，React + Ink 画界面，Bun 打包。
- 是**打包版，不能直接运行**；`feature()` 是**构建期开关**，看到的分支未必存在。
- 数据流主干：`cli.tsx` → `main()` → `setup()` → REPL → `query()` 循环 → `api/claude.ts` → 工具 → 回灌。
