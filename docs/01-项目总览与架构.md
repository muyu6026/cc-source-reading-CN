## 1.1 这个项目是什么：一张身份证

先把能从仓库里直接核实的「身份证信息」抄下来（出处：[`source/package.json`](../source/package.json)）：

| 字段 | 值 | 这说明什么 |
|------|-----|-----------|
| `name` | `@anthropic-ai/claude-code` | 官方发布的 npm 包，作用域 `@anthropic-ai` |
| `version` | `2.1.88` | 你手上这份源码对应的版本 |
| `bin` | `{"claude": "cli.js"}` | 装完之后终端里的命令叫 `claude`，指向打包产物 `cli.js` |
| `type` | `"module"` | 全仓 ESM（`import`/`export`），不是老的 CommonJS |
| `engines` | 有 Node 版本门槛 | 对运行环境有硬性要求 |
| `dependencies` | `{}`（**空**） | 依赖全部在打包时被 Bun 内联了（见 1.3 坑 1） |

**一句话定位**：这是一个跑在终端里的 AI 编程智能体——你说人话，它读你的代码库、改文件、跑命令，多步自主干活直到任务完成。

**「agentic（智能体化）」到底指什么**：普通的 AI 对话是「一问一答」；这里的区别是模型可以**主动发起动作**——它在回答里说「我要读一下 a.txt」，程序就真的去读文件、把内容塞回对话、让模型继续。这个「模型说 → 程序做 → 结果回灌 → 模型再说」的循环，就是整个项目的核心（1.6 节逐帧拆解）。

### 它不止一种形态

很多人以为它「只是一个命令行工具」，从入口文件看它至少有四种运行形态（出处：[`src/entrypoints/`](../source/src/entrypoints/) 目录实存文件）：

| 形态 | 证据 | 干什么 |
|------|------|--------|
| 交互式终端（REPL） | `entrypoints/cli.tsx` → `main.tsx` | 你平时敲 `claude` 进入的那个界面 |
| 无头打印（print 模式） | `cli/print.ts`（5,594 行，全仓第一大文件） | `claude -p "问题"`：跑完直接输出答案退出，给脚本用 |
| SDK（给别人编程用） | `entrypoints/sdk/`（3 份：`coreSchemas.ts` 1,889 行、`controlSchemas.ts` 663 行、`coreTypes.ts` 62 行） | 把整套智能体能力以库的形式暴露给其他程序 |
| MCP 服务器 | `entrypoints/mcp.ts`（196 行） | `claude mcp serve`：把 CC 自己变成一个可被别的 AI 调用的工具服务器 |

> **验证命令**（在仓库根目录跑）：
> ```
> ls source/src/entrypoints source/src/entrypoints/sdk
> python -c "import json;print(json.load(open('source/package.json'))['bin'])"
> ```
> 你会看到上面表格里的每一个文件都真实存在。

## 1.3 必须先懂的四个坑（每个都附真实代码位置）

### 坑 1：这是打包版源码，不能直接跑

`package.json` 的 `dependencies` 是空对象 `{}`——运行依赖在构建时被 Bun 打进 `cli.js` 了。所以：

- `npm install` 之后**跑不起来**，也不要试；
- 正确心态：把它当**源码阅读对象**，配合本仓库的批注版读；
- 想体验程序本身，去装官方发行的 Claude Code，别用这份源码。

### 坑 2：`feature('XXX')` 是构建期开关，你看到的分支未必存在

源码里到处是：

```ts
if (feature('KAIROS')) {
  // 这段代码只有开关打开时才会被打进最终包
}
```

这是 Bun 打包期的**死代码消除（DCE）**：开关没开，整段代码在打包时被删掉，最终产物里**根本不存在**。

**实算一下这个机制的使用密度**（验证命令：`grep -rEo "feature\('[A-Z_]+'\)" source/src -h | sort | uniq -c | sort -rn | head`），开关按出现次数排前几名：

| 开关 | 次数 | 大致含义（从上下文推断） |
|------|------|--------------------------|
| `KAIROS` | 154 | 内部试验项目（代号） |
| `TRANSCRIPT_CLASSIFIER` | 107 | 对话记录分类器 |
| `TEAMMEM` | 51 | 团队成员相关 |
| `VOICE_MODE` | 46 | 语音模式 |
| `BASH_CLASSIFIER` | 45 | bash 命令分类器 |
| `PROACTIVE` | 37 | 主动提示 |
| `COORDINATOR_MODE` | 32 | 多智能体编排模式 |
| `BRIDGE_MODE` | 28 | 远程桥接（`claude remote-control`） |

全仓 **199 个文件**至少用了一次 `feature()`。读代码三原则：

1. 看到不熟悉的功能，先怀疑「是不是内部版才有的」；
2. 别试图「跑通」这些分支——你的版本里可能连实现都没有；
3. 开关名**必须内联写在判断那一行**，提出去变量 DCE 就失效了——这是个刻意为之的约束（见 [`cli.tsx`](../annotated/src/entrypoints/cli.tsx) 第 200–209 行的注释原文）。

**进阶：双层开关设计**。`cli.tsx` 的 remote-control 分支展示了构建期/运行期两层开关的配合：

- 构建期：`feature('BRIDGE_MODE')` 决定「这段代码**在不在**发布包里」；
- 运行期：`isBridgeEnabled()` 查 GrowthBook（服务端下发的实验开关）决定「功能**开不开**」。

两个维度别混淆——代码在、功能关，和代码不在，是两回事。

### 坑 3：`import` 写 `.js`，文件却是 `.ts`

```ts
import { profileCheckpoint } from '../utils/startupProfiler.js';
```

文件明明是 `startupProfiler.ts`，导入却写 `.js`——这是 NodeNext 模块解析的约定：**编译后**的文件是 `.js`，导入路径按产物写。0 基础读到这里几乎必然困惑，记住「写 .js 指 .ts」即可，详见 [00a TypeScript 地基 · 1.5 节](00a-TypeScript地基.md)。

### 坑 4：入口文件的「顶层副作用」是故意的

[`cli.tsx`](../annotated/src/entrypoints/cli.tsx) 一开头（第 38–80 行）就在模块顶层改环境变量：

```ts
process.env.COREPACK_ENABLE_AUTO_PIN = '0';
if (process.env.CLAUDE_CODE_REMOTE === 'true') {
  process.env.NODE_OPTIONS = existing ? `${existing} --max-old-space-size=8192` : '--max-old-space-size=8192';
}
```

一般工程规范禁止顶层副作用（所以满屏 `eslint-disable` 豁免注释），但**环境变量必须早于一切读者**——放进函数里就晚了：别的模块在 `import` 的瞬间就把某些 env 读进了模块级常量（`cli.tsx` 第 59–66 行注释原文解释了 BashTool/AgentTool 会 `import` 时捕获 `DISABLE_BACKGROUND_TASKS`）。这是「顺序即正确性」的实例。

## 1.5 启动链路：从 `claude` 到 REPL 的三棒接力

### 第 1 棒：`cli.tsx` —— 先分流，再加载大块头

[`cli.tsx`](../annotated/src/entrypoints/cli.tsx) 的核心设计：**`--version` 这类请求不该为 789 KB 的 `main.js` 买单**。它维护了一张「快速路径表」，每个分支都抢在 `await import('../main.js')` 之前 `return`：

| 快速路径 | 干什么 | 值得注意的细节 |
|----------|--------|----------------|
| `--version` / `-v` | 打印版本退出 | `args.length === 1` 才算——`--version --foo` 不走快速路径；版本号是打包时内联的字面量 |
| `--dump-system-prompt` | 打印渲染好的系统提示词 | 内部评测专用，`feature('DUMP_SYSTEM_PROMPT')` 从外部构建删除 |
| `--claude-in-chrome-mcp` | 启动 Chrome 桥接 MCP 服务器 | 对应 [`utils/claudeInChrome/mcpServer.ts`](../annotated/src/utils/claudeInChrome/mcpServer.ts)（第 64 批刚批注） |
| `--chrome-native-host` | 当浏览器的「原生消息宿主」 | Chrome 扩展与本地进程的通信通道 |
| `--computer-use-mcp` | 启动电脑操控 MCP 服务器 | 代号 `CHICAGO_MCP` |
| `--daemon-worker=<kind>` | 被 supervisor 拉起的精简 worker | **故意不**初始化配置与埋点，保持精简 |
| `remote-control` / `rc` / `remote` / `sync` / `bridge` | 把本机变成远程可操控环境 | 四道闸顺序固定：登录→GrowthBook→版本→企业策略 |
| `daemon` | 常驻监督进程 | 与 worker 相反，**要**初始化埋点（要长期跑） |
| `ps` / `logs` / `attach` / `kill` / `--bg` | 后台会话管理 | 数据在 `~/.claude/sessions/` 注册表 |
| `new` / `list` / `reply` | 模板任务 | 全文件唯一用 `process.exit(0)` 的分支（Ink 句柄导致退不出，注释原文有解释） |
| `environment-runner` / `self-hosted-runner` | 无头执行器 | BYOC / 自托管两种部署 |
| `--tmux` + `--worktree` | 先 exec 进 tmux 再说 | 失败要**落回**正常流程，先判 `handled` 再判 `error` 的顺序有讲究 |

都没命中，才走到兜底：**先** `startCapturingEarlyInput()`（抢在加载大文件前挂上键盘监听——加载要几百毫秒，用户可能已经开始打字了，一个字符都不能丢），**再** `await import('../main.js')` 加载完整 CLI。每一步都打 `profileCheckpoint` 时间戳，启动慢了能定位卡在哪段。

> 精读这一文件：[`annotated/src/entrypoints/cli.tsx`](../annotated/src/entrypoints/cli.tsx)，302 行原文全部带中文批注，是学习路线 [L1-5 单元](00-零基础学习路线.md)的指定教材。

### 第 2 棒：`main.tsx` 的 `main()`（4,684 行，全仓第二大文件）

解析 commander 参数、装配配置、决定交互/非交互模式，然后调 `setup()` 初始化、`render` 出 REPL。这文件还没批注（它是后续批注批次的重头），初学**不要**直接啃——先读第 3 棒和主循环。

### 第 3 棒：`setup.ts` 的 `setup()`（477 行，已批注）

初始化清单（详见 [03 启动流程](03-启动流程.md)）：Node 版本守卫、工作区信任检查、hook 配置抓取、插件预热、`tengu_started` 埋点。批注版：[`annotated/src/setup.ts`](../annotated/src/setup.ts)。

## 1.6 一次完整交互的 15 步（每步给出处）

以「帮我把 a.txt 里的 foo 改成 bar」为例，这 15 步覆盖了「智能体」一词的全部实现：

| # | 发生什么 | 出处文件 | 备注 |
|---|----------|----------|------|
| 1 | 入口分流，非快速路径 | [`entrypoints/cli.tsx`](../annotated/src/entrypoints/cli.tsx) | 1.5 节那张表 |
| 2 | `main()` 解析参数 | `src/main.tsx` | 4,684 行 |
| 3 | `setup()` 初始化 | [`setup.ts`](../annotated/src/setup.ts) | 477 行 |
| 4 | 渲染 REPL，等你输入 | `src/screens/REPL.tsx` + `ink/` | 5,980 + 19,859 行 |
| 5 | 你敲回车，消息进入查询管线 | `src/query.ts` | 1,729 行 |
| 6 | 主循环第 1 轮：消息 + 系统提示词 + 工具清单发给 API | `services/api/claude.ts` | 流式返回 |
| 7 | 模型返回 `tool_use: Read(a.txt)` | —— | 模型主动要求动手 |
| 8 | 权限判定 | `utils/permissions/permissions.ts` 等五方竞速 | 读文件通常是 `allow` |
| 9 | 执行工具 | `services/tools/` 流水线 | 真的去读文件 |
| 10 | 结果回灌为 `tool_result` | `utils/messages/` | 塞回消息列表 |
| 11 | 第 2 轮循环：模型看到文件内容 | `query.ts` 的 `while(true)` | 上下文变长了 |
| 12 | 模型返回 `tool_use: Edit(a.txt, foo→bar)` | —— | 改文件默认 `ask`，弹窗问你 |
| 13 | 你同意 → 执行 → 返回 diff | `tools/FileEditTool/`（已批注） | 十个 errorCode 校验链 |
| 14 | 第 3 轮：模型判断完成，返回纯文本 | —— | 不再要求工具 |
| 15 | 跳出循环，渲染最终回答 | `ink/` 渲染管线 | token 花费同时记账（`cost-tracker.ts`） |

**第 6~14 步就是「AI 智能体」的全部秘密**：一个 `while(true)`，每轮把「消息历史」发给模型，模型要么回话、要么要工具，工具结果回灌，循环到模型不再要工具为止。没有任何魔法。第 06 篇会把循环本体的代码逐段讲给你。

## 1.8 合书自测（不翻书写出答案才算过）

1. `claude --version` 为什么快？它最多加载几个模块？`claude --version --foo` 也走这条路径吗？
2. `feature('KAIROS')` 出现 154 次——这些代码在你手上的发布版里存在吗？为什么这种判断必须内联写在 `if` 那一行？
3. `import ... from '../utils/config.js'` 找不到 `config.js` 文件，为什么还能工作？
4. `cli.tsx` 顶层就改 `process.env`，违反了哪条工程规范？为什么它是对的？
