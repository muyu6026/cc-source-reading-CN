## 2. 精读正文（逐行，行号为批注版行号）

### 2.1 第 1 行：把两个工具拿进来

```ts
import { useEffect, useState } from 'react'
```

**念法**：
> 「从 `react` 这个模块里，取出 `useEffect` 和 `useState` 两个东西，后面直接用名字。」

两个都是 React 的 **hook**（钩子）——以 `use` 开头的函数，只能在组件或别的 hook 里调用。`useState` 负责存一个会变的值，`useEffect` 负责「在某个时机做一件事」（这里是起计时器）。

这条 `import` 没有 `type` 关键字，说明它要的是真东西（运行时会保留）；对比讲义 [§4.1](../00a-TypeScript地基.md) 的 `import type`，那种编译后整行消失。

### 2.2 第 3–4 行：函数签名，一行里三个标签

```ts
export function useTimeout(delay: number, resetTrigger?: number): boolean {
// 延时 hook：delay 毫秒后把 isElapsed 翻 true；resetTrigger 变化会重置计时器（再次开始计时）。
```

第 3 行是整节课的核心，拆成六段读：

| 片段 | 念法 |
| --- | --- |
| `export` | 「这个函数给外面用」（其他文件能 `import` 它） |
| `function useTimeout` | 「定义一个叫 `useTimeout` 的函数」 |
| `(delay: number` | 「第一个参数叫 `delay`，**必须是数字**」 |
| `, resetTrigger?: number` | 「第二个参数叫 `resetTrigger`，**可以不给**，给了就得是数字」 |
| `)` | 参数列表结束 |
| `: boolean {` | 「**这个函数返回布尔值**」，然后才是函数体 |

**关键区分（0 基础第一个坑）**：`)` 后面那个 `: boolean` 不是参数类型，是**返回值类型**。写返回值类型的位置在参数列表的右边、函数体的左边。

第 4 行是批注，不是代码。它告诉你 `resetTrigger` 的用途：**不是用来读的，是用来「踢一脚」的**——它的值一变，`useEffect` 就重跑，计时器从头开始。

### 2.3 第 5 行：没写类型，却自动有了类型

```ts
  const [isElapsed, setIsElapsed] = useState(false)
```

**念法**：
> 「调 `useState`，初始值 `false`；它返回一个两元素数组，第一个叫 `isElapsed`（当前值），第二个叫 `setIsElapsed`（改它的函数）。」

`const [a, b] = ...` 是**数组解构**（讲义 [§2.2](../00a-TypeScript地基.md)）：按位置取，不是按名字取。`useState` 返回的固定是「值 + 改值函数」这个顺序，所以左边的名字可以自己起。

**为什么 `isElapsed` 自动是 `boolean`**：类型推断。`useState` 是个泛型函数，签名大意是 `useState<T>(初始值: T): [T, (新值: T) => void]`。你给 `false`，编译器就把 `T` 定成 `boolean`，两个返回值跟着都定了型。

仓库里**没人写** `useState<boolean>(false)`——`grep -rn "useState<boolean>" source/src | wc -l` 的结果是 `0`。能推断出来的，作者就不手写；这条习惯贯穿全仓。

### 2.4 第 7–9 行：effect 里起计时器

```ts
  useEffect(() => {
    setIsElapsed(false)
    const timer = setTimeout(setIsElapsed, delay, true)
```

第 7 行 `useEffect(() => {` 传进去一个**箭头函数**——注意是「把函数交出去」，不是「现在执行」。React 会在渲染之后替你调用它。

第 8 行：每次重跑先把状态复位成 `false`。少了这行，`resetTrigger` 变化后 `isElapsed` 会停在 `true`，计时器却已经重新开始了——状态和计时器不同步。

第 9 行是本节最容易读错的一行：

```ts
setTimeout(setIsElapsed, delay, true)
```

**念法**：
> 「`delay` 毫秒后，调用 `setIsElapsed`，并把 `true` 当第一个参数传给它。」

三个位置分别是：**到点要执行的函数** / **等多久** / **传给那个函数的参数**。所以它等价于「`delay` 毫秒后执行 `setIsElapsed(true)`」。

**不要读成**「现在调用 `setIsElapsed`」——这里 `setIsElapsed` 后面没有圆括号，它是被**当值传出去**的。这就是 L0-07 要展开的主题：函数也是值。

### 2.5 第 10–13 行：清理函数与依赖数组

```ts
// 每次 effect 先复位为 false 再起计时器；delay / resetTrigger 变化时清理旧计时器重来。

    return () => clearTimeout(timer)
  }, [delay, resetTrigger])
```

第 12 行 `return () => clearTimeout(timer)`：effect **返回了一个函数**。React 把它记下来，在两种时机调用它——组件卸载时，或依赖变化、准备重跑 effect 之前。这叫**清理函数**。

**它解决什么**：不清理的话，每改一次 `resetTrigger` 就多一个计时器在跑，旧的到点仍会把 `isElapsed` 翻成 `true`。清理保证了「任何时刻只有一个计时器」。

第 13 行 `[delay, resetTrigger]` 是**依赖数组**：里面列的东西变了，effect 就重跑。`delay` 变了要重新计时，`resetTrigger` 变了要「重新开始」，所以两个都在里面。

### 2.6 第 15–16 行：返回布尔值

```ts
  return isElapsed
}
```

`return isElapsed` 返回的是 `boolean`，和第 3 行 `: boolean` 对得上。**类型注解是一份承诺**：写 `: boolean` 却 `return 'yes'`，编译期就过不去。

## 3. 三个问题（路线图 L0-5 卡片）

### 问题 1：`resetTrigger?` 里的 `?` 和 `delay` 有什么区别？调用时少传哪个会报错？

**区别在「必填」与「选填」**：

| 参数 | 写法 | 必须传吗 | 类型 |
| --- | --- | --- | --- |
| `delay` | `delay: number` | **必须** | `number` |
| `resetTrigger` | `resetTrigger?: number` | 可以不传 | `number \| undefined` |

`?` 加在**参数名后面**，含义是「这个位置可以空着」（讲义 [§2.3](../00a-TypeScript地基.md) 的第一行）。它**不是**「可以是 null」，也不是「类型不确定」——`resetTrigger` 的真实类型是 `number | undefined`。

**少传 `delay` 会报错**：它是必填参数。调用 `useTimeout()` 时，TypeScript 会在编译期报「参数个数不对」类的错误（这份仓库只用于阅读，没有可跑的编译环境，所以不贴报错原文，只讲规则）。

**少传 `resetTrigger` 不报错**，仓库里有真实例子：

```ts
const showSpinner = useTimeout(1000) && isChecking;
```

出处 [`source/src/utils/preflightChecks.tsx`](../../source/src/utils/preflightChecks.tsx) 第 85 行。只传了一个 1000，第二个参数整个省掉——因为这里不需要「重置」，一次启动检查只需要计一次时。

### 问题 2：`useState(false)` 没写类型，`isElapsed` 为什么自动是 `boolean`？

因为**类型推断**：编译器从初始值 `false` 反推出泛型参数 `T = boolean`，于是返回的二元组被定成 `[boolean, 修改函数]`。

拆开看 `useState` 的形状（这是理解推断的关键）：

```
useState<T>(初始值: T)  →  [T, (新值: T) => void]
                ↑ 你给 false，T 就被定成 boolean
```

三个连带结果：

1. `isElapsed` 是 `boolean`，能直接放进 `if` 或和 `&&` 连用（第 85 行那个 `useTimeout(1000) && isChecking` 就是把它当布尔值用）；
2. `setIsElapsed(true)` 合法，`setIsElapsed('yes')` 编译期报错；
3. 想改类型不能靠「后面赋个别的值」，得改初始值或显式写 `useState<类型>(...)`。

**推断不是「不检查」**：编译器自己算出来，然后照样严格检查。

### 问题 3：`const [a, b] = ...` 这个方括号是什么写法？

是**数组解构**（讲义 [§2.2](../00a-TypeScript地基.md)）。

```ts
const [isElapsed, setIsElapsed] = useState(false)
```

**念法**：
> 「右边给我一个数组，我按顺序把第 0 个叫 `isElapsed`、第 1 个叫 `setIsElapsed`。」

和理解它有关的三个点：

- **按位置，不按名字**。`useState` 返回的数组里没有字段名，所以名字由你定；写成 `const [x, y]` 完全合法，只是可读性差。
- **可以只取一个**：`const [isElapsed] = useState(false)` 合法（第二个丢掉）。
- 对比**对象解构**（讲义 §2.2 第二小节）：对象按**字段名**取，数组按**顺序**取。看到 `{` 想字段名，看到 `[` 想位置。

## 4. 常见误读

| ❌ 0 基础最可能这样读 | ✅ 实际是什么 |
| --- | --- |
| `): boolean {` 里的 `boolean` 是某个参数的类型 | 是**返回值**类型。参数类型都在圆括号里，每个参数各自带一个 |
| `resetTrigger?` 表示「可以传 null」 | 表示「这个参数可以不传」，类型是 `number \| undefined`；`null` 不在里面 |
| `setTimeout(setIsElapsed, delay, true)` 是「立刻调用 setIsElapsed」 | 只是把函数**当值传出去**；到点后 React 那边才替你调用 `setIsElapsed(true)` |

## 6. 合书自测

1. 默写一个「接收两个数字、返回字符串」的函数签名（只要签名，不要函数体）。
2. `useTimeout(500)` 合法吗？为什么？
3. `isElapsed` 的类型是什么？这个类型是谁定的？
4. `const [a, b] = useState(false)` 里，`b` 是什么？它的类型是什么？
5. `resetTrigger` 从 `1` 改成 `2`，会发生什么？靠哪一行机制？
6. 把第 12 行 `return () => clearTimeout(timer)` 删掉，会出现什么现象？

<details>
<summary>参考答案（先自己写，再展开）</summary>

1. `function f(a: number, b: number): string { ... }`。要点：两个参数各带 `: number`，圆括号后写 `: string`。
2. 合法。`delay` 必填且已给；`resetTrigger` 带 `?`，可以不传。仓库第 85 行的 `useTimeout(1000)` 就是这么用的。
3. `boolean`。由 `useState(false)` 的初始值推断出来（`T` 被定成 `boolean`），不是手写的。
4. `b` 是修改函数（这里是 `setIsElapsed`），类型是「接收新值、返回 void」的函数，即 `(新值: boolean) => void`；严格说它还能接收一个「旧值 → 新值」的函数。
5. `useEffect` 的依赖数组 `[delay, resetTrigger]` 发现变了 → 先跑上一次返回的清理函数（清掉旧计时器）→ 再跑一遍 effect（复位 `false`、重新 `setTimeout`）。所以计时从头开始。
6. 每次依赖变化都会多出一个计时器，旧的到点仍会把 `isElapsed` 置为 `true`；表现为「计时提前结束」或「状态乱跳」。React 不管清理，清理必须由 effect 自己返回。

</details>
